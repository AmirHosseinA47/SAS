1. WHAT WAS BUILT
--------------------------------------------------------------------------------
Five source files: 246 insertions, 7 deletions (the 7 are lines replaced in place -
   the two accessors rewritten for the float guard, the nofuel comprehension, and
   two renderer branches). Plus one new test file, tests/test_depot_fireproof.py.

1.1 THE CLEAR. wildfire_model.reset() calls a new _fireproof_base_station()
    immediately after the station is built. It iterates the depot cell set -
    station["cells"], the UNION over depots, sorted - and calls the EXISTING
    agents.Fire.firefighter_remove_fuel() on each cell's Fire agent. No new write
    path, exactly as the design asked.

    THE PLACEMENT IS LOAD-BEARING AND WAS CHECKED, NOT ASSUMED. At that line
    set_fire_agents() has run, so every Fire agent exists and has ALREADY DRAWN
    its fuel; _build_base_station() has run, so the cell set exists; and no UAV
    has been placed yet, so the only grid occupants are Fire agents. reset() has
    exactly one caller (__init__) and both new attributes are re-initialised at
    the top of the method, so a second call is idempotent.

1.2 THE SWITCHES, in common_fixed_variables.py:
      BASE_STATION_FIREPROOF          shipped 1
      BASE_STATION_FIREPROOF_DRY_RUN  shipped 0
    read through accessors in agents.py at call time via the cfv module - never
    star-imported - so an apply_scenario_config override is visible. The
    fireproof accessor falls back to the SHIPPED value like every other
    base-station accessor, which carries that family's recorded hazard: a junk
    override ARMS it. The comment says so.

    A FLOAT HOLE THAT AN ADVERSARIAL PASS FOUND AND THAT IS NOW CLOSED. The first
    version used a bare `int(x) != 0`. int(0.5) is 0, and the harness's own
    --set parser produces a float for "0.5", so `--set BASE_STATION_FIREPROOF=0.5`
    would have run the OFF path while params recorded 0.5 - a non-zero value
    disarming the feature with nothing anywhere saying so. Both accessors now do
    what ff_firefight_mission_gate does: a non-integral float falls back.
    tests/test_depot_fireproof.py::test_a_fractional_override_cannot_silently_-
    flip_either_switch pins it.

1.3 THE DISPLAY. A cell with no fuel that has never burned rendered
    VEGETATION_COLORS[0] = #414141 - which is also FIRE_COLORS[0], sits in the
    burnt/smoke grey band, and says "spent" about ground that never burned. It
    now renders a measured #193cff on BOTH surfaces (serve_dashboard._cell_color
    and main.agent_portrayal), with a "cleared (no fuel)" legend chip in BOTH
    legend branches, refreshed on the probability toggle. Because probability
    mode paints the ground from the probability ramp alone and a cleared cell's
    probability is 0 forever, the frame payload gained one key, `nofuel`, and
    drawMap paints those cells in probability mode too - otherwise the chip in
    the probability branch would name a colour that is not on screen.

1.4 WHAT THE PREDICATE COVERS, SAID PLAINLY. The branch is keyed on the CELL's
    physics - fuel 0, never burned, not burning, not burnt - not on depot
    membership. Two things produce that state: this round's depot clear, and a
    firefighter FIREBREAK from the fire-mechanic round. They are the same
    physical state and get the same colour. Keying on depot membership instead
    would have made the two surfaces disagree, because the mesa canvas has no
    depot knowledge at all.

THE DEPOT-CELL COMPONENT IS EXACT ARITHMETIC. In the armed arm ZERO depot cells
ever burn, in all 37 paired runs. So the control's own per-run counts ARE the

  over 37 paired runs        untouched vegetation      burnt_cells
  predicted by the depot          +907                    -610
  observed                       +3029                   -2002
  BEHAVIOURAL REMAINDER          +2122                   -1392

A fuel-less never-burned cell is counted as UNTOUCHED VEGETATION by the ground
counts (has_burned 0, burnt 0, burning 0) although it has no fuel. "Intact" rises
without a single tree being saved; that is the whole of the predicted term, and
it is the reason the two numbers differ.

IS THE REMAINDER SIGNAL OR NOISE? The per-run distribution:

  untouched     mean  +57.4   sd 124.3   se 20.4   mean/se +2.81   signs +24 /-10 / 0 3
  burnt_cells   mean  -37.6   sd  96.7   se 15.9   mean/se -2.37   signs +11 /-23 / 0 3

The null it is against is the fire-mechanic round's measurement of a WRITE-FREE
draw-stream offset, which moved final intact by a median of 155 cells with NO
systematic sign. This remainder is about 2.8 standard errors from zero and its
signs are lopsided 24 to 10, which is a real effect and not a large one: 50 cells
stop being IGNITING NEIGHBOURS, and the 34 cells within Euclidean 3 of each
corner block see a lower ignition probability during the window when the depot
would have been burning. That is the "local dent" Part 1 predicted, now measured.

Two caveats on that inference, both of which cut against it:
  - the 37 runs are not 37 independent fires. east/default/{101,202,303} share
    their fire with east/half/{101,202,303}, so the effective n is about 34.
  - 2.8 se on one sample is suggestive, not settled. This project has three
    recorded cases of a gain evaporating on a wider seed set. It is reported as a
    measured tendency, and NOTHING in the gate rests on it.

8. THE COLOUR  (decision 6.3)
--------------------------------------------------------------------------------
#193cff, chosen by an exhaustive CIEDE2000 sweep over 140,608 colours, not by eye.
outputs/_dfp_colour.py -> outputs/_dfp_colour.txt.

THE INSTRUMENT is the base-mark round's, not a re-transcription: the script reads
outputs/_bm_colour_a.py as text and runs its library block verbatim (sRGB ->
linear -> XYZ D65 -> CIELAB -> CIEDE2000, Machado 2009 CVD matrices at severity
1.0). It is re-validated on the 9 Sharma et al. pairs lifted from
outputs/_sc_deltae.py and cross-checked against that file's INDEPENDENT scalar
implementation on real palette pairs (worst disagreement 3.2e-3, entirely the two
white-point conventions).

THE PALETTE is N+ = 164 entries: the four ramps parsed from source, every
single-state map literal, every unit marker, and every one of those composited
under the depot fill, under the gridline, and under both. The candidate is scored
across ALL FOUR of its own rendered forms (plain, gridlined, depot-tinted, both)
and four vision conditions; the worst is kept.

  #193cff   normal 12.85 | protanopia 6.69 | deuteranopia 8.51 | tritanopia 8.20
  worst chromatic condition 6.69 dE. No exact-hex collision. L* 39.0.
  Its four forms: #193cff / #1531d1 / #2e2fe9 / #2b26c5.

THE BAR, and it had to be corrected twice in this round's favour's disfavour. The
first version of the reference table scored the shipped colours against their OWN
gridline composites and against probability-mode entries that can never be on
screen in the same frame as a map-mode ground colour. Both errors FLATTERED the
new colour. Corrected - self-composites removed, each reference scored only
against entries that can co-occur with it:

  shipped colour        normal   worst chromatic
  scorched #895e00      14.29        0.46
  burnt    #2b2b2b       3.20        2.08
  spared   #2f4a1a       4.00        1.52
  depot    #770099      17.22        9.44
  VEG[0]   #414141       4.07        3.61
  smoke    #ababab      11.16        9.45
  firefighter #00ffcc   14.37        4.32

  The weakest shipped map colour is 3.20 normal / 0.46 worst-chromatic. #193cff's
  12.85 / 6.69 clears it, and is second only to the depot violet on the chromatic
  axis - while being scored over four forms where every reference is scored over
  one. The original claim survived the correction.

WHY NOT THE WORST-OF-FIVE OBJECTIVE. Scored worst-of-five, the ACHROMATIC
condition caps ANY colour in this palette at 0.76 dE - 164 entries tile the
greyscale range. Every colour this repo ships fails it (0.13 to 0.74). Making it
a veto would set a standard nothing meets and would drive the choice to
near-black, the burnt band this colour must not read as. The objective is the
worst of the four CHROMATIC conditions; all five are reported.

THREE THINGS AN ADVERSARIAL PASS CHANGED, all recorded in the artifact:
  - #00BFFF (the mesa PathMarker) was missing from the palette. A REVERSE CHECK
    now scans both renderers for every #rrggbb literal and requires each to be in
    the palette or in a NAMED page-chrome list; 31 in palette, 16 chrome, 0
    unaccounted. A presence assertion, which is all the base-mark instrument had,
    catches a literal that vanishes but not one that is added.
  - The L* 22..82 floor is relabelled as what it is: not a confusion the sweep
    missed (#00006e is 27.98 dE from burnt) but a proxy for the achromatic
    condition that is deliberately not vetoed on. It costs 21% of the objective
    (ceiling 8.65 -> 6.82) and that price is stated.
  - The tie-break's band width is a free parameter and is reported as one: 0.05
    elects #4137ff (2.30 dE away), 0.25 elects #053cff (1.9 dE away). Every band
    member is the same deep blue, clears the bar and binds against #770099. The
    band width moves the shade, not the decision.

11. COMMON RANDOM NUMBERS: REMOVING THE 6.5 PROBLEM RATHER THAN WORKING AROUND IT
--------------------------------------------------------------------------------
THIS IS THE ROUND'S METHODOLOGICAL POINT, and it is worth stating as one.

Decision 6.5 is right: when a change perturbs the fire's shared RNG stream, every
seed downstream is re-rolled and per-seed outcome signs are noise, so judge the
re-rolled seeds on AGGREGATE. This round followed that rule - and then went
further, because the rule is also a ceiling. With 16 of the 23 gate seeds
re-rolled, obeying it means the round can report pooled numbers and NOTHING per
seed, and an apparent pooled loss has no way to be examined.

So a third wave, 66 runs, did not work around the re-roll - it REMOVED THE REASON
FOR THE RULE, making per-seed comparison valid again. Two things came out of that
which aggregate-only judgement could not have produced:

  - the west/north pooled -2 became +0, per seed, on all ten seeds. An apparent
    loss on the sample decision 6.4 added turned out to be nothing at all; across
    all 33 pinned pairs rescued is +3 with no per-seed decrease anywhere.
  - the EXPOSURE SPLIT became attributable. In the stock arms only the depot
    component could be claimed (the search component moves with the re-roll).
    Under CRN the whole E1 fall is attributable and splits 0.27pp depot +
    0.14pp genuine search-component improvement.

The cost was 66 runs, about 1.5 hours, and it is reusable by any round in this
campaign whose change perturbs the fire stream.

THE INSTRUMENT. outputs/_fm2_probe_harness.py wraps the frozen harness and, with
--set FM2P_CRN=1, replaces Fire.step's single draw with
crn_uniform(seed, the cell's unique_id, that cell's steps_counter) - a pure
function. Clearing 50 cells' fuel then CANNOT shift the draw of any other cell.
Nothing is re-rolled, every seed is pinned, and a difference is PHYSICAL.
Two arms, dfpCB (6281542 checkout) and dfpCON (feature), on the canonical 13,
the fresh 10 and the west/north 10. THEY COMPARE ONLY WITH EACH OTHER: a CRN
fire is a different, equally distributed realisation, so these are not a second
measurement of dfpB / dfpON and are labelled as a different instrument. (The
fire-mechanic round left pinned-replay vs CRN unresolved on a firebreak's
physical size; this round does not resolve it either.)

  sample         runs   rescued        dead         ff_deaths

12. A RECURRING DEFECT CLASS, NOT A ONE-OFF
--------------------------------------------------------------------------------
The float hole in section 1.2 is THE SECOND TIME IN THIS PROJECT that an
accessor's fallback silently disagreed with the default it claimed to have, and
the two instances are the same shape:

  fire-mechanic round 2   ff_firefight_mission_gate. Its conservative value is ON
                          and its fallback is 1, but a bare int() cast would have
                          read 0.5 as 0 and turned the gate OFF. That round caught
                          it and added `if isinstance(raw, float) and raw != value:
                          return True` (agents.py), with the reason in its
                          docstring.
  this round              base_station_fireproof / _dry_run. Same bare cast, same
                          truncation, opposite direction: --set BASE_STATION_-
                          FIREPROOF=0.5 would have run the OFF arm while params
                          recorded 0.5.

THE COMMON SHAPE: an accessor states a fallback in prose, then implements a
coercion (`int(x) != 0`) whose domain is wider than the prose - so there exists a
value that parses, is non-zero, is recorded faithfully in the run's params, and
still takes the branch the prose says it would not. The harness's own --set
parser produces floats, so the value is reachable from the command line.

WHY IT KEEPS HAPPENING: the file's stated policy is about WHICH WAY a fallback
should point (shipped value for base-station keys, OFF for fire-mechanic action
keys). It says nothing about the coercion, so each new accessor re-derives that
part, and `int(x) != 0` is the obvious thing to write. The fix that exists is a
guard on one accessor, copied by hand.

WHAT WOULD ACTUALLY CLOSE IT: a single coercion helper the accessors call, or a
test that enumerates every accessor in agents.py against the fractional values -
tests/test_base_station.py::test_accessors_survive_junk_values already binds
every base-station accessor to cfv and would be the natural place. This round
added the fractional case for its OWN two accessors only
(tests/test_depot_fireproof.py::test_a_fractional_override_cannot_silently_flip_-
either_switch). The other eleven base-station accessors and the five
fire-mechanic ones are NOT covered, and at least base_station_mode,
base_station_size, base_station_spawn_split and base_station_dock_fix have the
same bare-cast shape. That is a small, separate piece of work.
