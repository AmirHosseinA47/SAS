## 1. The exact F5 rule replayed

The code is `fs_rules.py:82-101` (`bfs_first_step`) and `fs_counterfactual.py:59-95` (`replay`). Both are described in section 4.

- **BFS start:** the current position, recomputed at every advance k with that step's fire. `fs_counterfactual.py:75`: `nxt = bfs_first_step(env, pos, k)`.
- **Start cell is exempt.** `fs_rules.py:86-87`: `prev = {pos: None}; q = deque([pos])`. The start is never filtered and never tested as a goal. A carrier standing on a burning cell still searches. A carrier already on the boundary would step to another boundary cell rather than complete.
- **Passable test**, `fs_rules.py:90-94`: `if n in prev or env.burning(n, k): continue` / `if strict and (env.adj(n, k) or env.smoky(n, k)): continue`. So a cell must be in-bounds (N=50 is hard-coded, `fs_env.py:13-18`), not burning at k, and not fire-adjacent at k. Adjacent means any in-bounds 4-neighbour is burning, which includes the carrier's own cell (`fs_env.py:111-112`). It must also not be smoky: `smoky = (not burning) and smoke on`, `fs_env.py:108-109`.
- **The goal cell must itself be clean.** `fs_rules.py:95-96`: `prev[n] = c` / `if on_boundary(n):`. The goal test comes after the passable filter. So a fire-adjacent or smoky boundary cell is never a target.
- **Target set:** any cell with an out-of-bounds 4-neighbour (`fs_rules.py:10-11`). "Nearest" means the fewest steps over clean cells from the current position. It does not mean nearest to the pickup, and it is not a Manhattan distance.
- **Ties:** the goal test runs at discovery, so the first boundary cell discovered at the minimum depth wins. The path is rebuilt through first-discovery parents (`fs_rules.py:97-99`). Expansion order is `ORDER = ((1,0),(-1,0),(0,1),(0,-1))` (`fs_env.py:14`), the same as agents.py:1961.
- **No memory.** Nothing persists between steps except the local `tgt` described next.
- **"Falls back to today's rule"** (`fs_counterfactual.py:76-77`: `if nxt is None: nxt, _t = move_toward(env, pos, tgt, k)`) means the unchanged `_move_toward` rule, tiers 1-4, toward `tgt`. `tgt` is the recorded fixed exit_target, because it only changes right before a completion. The transcription is `fs_rules.py:39-79`, checked against agents.py:2369-2464.
  - If no neighbour is non-burning, the replay records a death when the carrier's own cell is burning, and otherwise holds (`fs_counterfactual.py:83-86`). The model's route_blocked drop (agents.py:2411-2413) is not modelled. I counted 0 such holds in the base and F5-with-F1 replays on the census and uhD sets.
- **How F1 was combined:** it was not. The F1 test at `fs_counterfactual.py:64` only fires for `("F1","F1F4","F1F6","F1F4s")`, and there is no F1+F5 rule in `RULES` (line 98). The F5 row completed through `elif on_boundary(nxt): tgt = nxt` (lines 78-79) and then `pos == tgt` (line 66). That is completion at a boundary cell the BFS stepped onto, one advance later, which is F1's timing.
  - I added a real F1+F5 rule (F1 test first, then F5). It is identical to F5 in every set: census 1643 / 20 / 12 / 3, uhD 588, uhY 548, uhC 519, ugKC 590, ugKD 597, ugKY 598. With fire held fixed, F1+F5 can only end a leg at the same step or earlier than F5.
  - **F1 is essential to mode 2, not an add-on.** All 59 changed census legs ended on a boundary cell other than the fixed exit_target, as did 5/5 in uhD, 2/2 in uhY, 4/4 in ugKC and 3/3 in ugKD. Without F1, or the replay's local reassignment, F5 would not complete those legs.
- **Step accounting.**
  - A leg is `(s0, p0)` = the last exit_start's step and position, paired with the victim's completion (`fs_counterfactual.py:33-43`). Only completed legs are included.
  - `n = k_completion - s0`, which counts the completion advance.
  - Stalled means `n > md(p0, recorded exit_target) + 5` (line 141).
  - Fire-adjacent and smoky steps count the carrier's cell after each move at the same k (lines 93-94).
  - A leg times out after 299 advances. This is not capped at the run's 360 steps, and smoke is reconstructed only up to `d["steps"]`.

## 5. Warnings for the design

- **The smoke and adjacency test on the final boundary cell.**
  - The replayed F5 refuses a fire-adjacent or smoky boundary cell (`fs_rules.py:91-96`).
  - That keeps, at the last step, the refusal the diagnosis showed protects nothing. exitstall_part1.txt:458-463: "Entering a non-burning exit cell cannot be fatal ...   - No F5 variant with a relaxed goal test was ever replayed. The candidate at :748 ("step onto a non-burning exit cell regardless of smoke or adjacency") was tested only as F4, "small gain" (:1524, :1660-1663).
  - Relaxing the goal test would depart from the estimate.
  - The existing `_path_exists_avoiding_fire` (agents.py:2318-2353) uses the opposite convention. Its docstring (2328-2332) says "The destination counts as reachable even when it is itself burning ... The source is never tested", and its only passable test is "not burning". Reusing it would silently change the rule.
- **The implementation must not store the path or change exit_target** (:1575-1576 "must not add new persistent carrying-leg state"; :1637-1638).
  - It must set `_last_move_tier` and `_last_move_risk`, because agents.py:1852 reads the tier.

  - agents.py:1784-1791 builds exit_target with H on the x axis and W on the y axis. That makes no difference on a 50×50 grid.

## (d) The minimal serving predicate and its reach

**Predicate.** A victim V is in custody if there is a firefighter marker F where:
- `F.rescued_victim` is V's marker (or has V's id),
- `F.exiting` is True,
- F is not dead and its status is not "dead",
