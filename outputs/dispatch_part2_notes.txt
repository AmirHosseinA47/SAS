2. IMPLEMENTATION READINGS AND DEVIATIONS
--------------------------------------------------------------------------------
P2-1 Inline helpers.  13.2 names _victim_route_distances / _victim_clean_approach;
  they are closures inside _joint_dispatch_point (d_of, clean_ok) over the one BFS
  per victim of interest and the one CLEAN BFS per contestable victim.  Same
  semantics.  PAPER: none.
P2-2 FROZEN (6.3) uses the incumbent plus every unit free at the start of the
  J-post (before the fill), per 6.7's order (PROGRESS precedes FILL).  PAPER:
  none.
P2-3 6.3's infinite-distance rule, implemented literally (R2 finding 3): when d
  or x is infinite the progress state is left unchanged and the binding is NOT
  evaluated that frame (no persistence count, no REPLACE).  Because the state is
  unchanged, cell_prev keeps the last evaluated cell: if THAT cell stays enclosed
  while the unit's own route is open (possible only after a gap of two or more
  cells between evaluations, e.g. after latched frames), the binding stays
  unevaluated until the cell reopens or the binding changes.  Re-anchoring would
  be a design change, so it was not made.  KNOWN LIMITATION: Limit 3 is
  conservative there (the incumbent is kept).  PAPER: one line in the
  limitations - "a binding is not judged while its progress reference cell is
  enclosed by fire".
P2-4 The would-have-been casualty write-off counter (D-6, 5.9, M6) lives in the
  model (T-J8 needs a test-visible counter; the instrument reads it).  It re-runs
  today's select for EVERY incident that reaches the skipped pairing tail, on the
  current state minus the units it already "took" earlier in the same step
  (legacy pairs incidents in drain order; R1 finding 3), and counts only a
  casualty's mark_unreachable.  It is a per-incident counterfactual ON THE
  DISPATCHER'S OWN STATE - after the first divergence the legacy world differs -
  so it is an estimate, neither a lower nor an upper bound (R3 note 16: it
  undercounts units legacy would take at its closed recycle / return kicks,
  which never pass this tail, and overcounts when an earlier incident's
  counterfactual "takes" one unit while J-pre actually bound another to that
  victim).  Its snapshot read
  (every marker, undetected ones included) is the only new read of the legacy D1
  snapshot: measurement only; T-INFO-c asserts that no J function reads what it
  writes.  PAPER: "would-have-been write-offs" are reported as a per-incident
  counterfactual estimate.
P2-5 J-pre timing versus legacy's pre-move pairing (R1 finding 6).  Legacy pairs
  a pre-move detection inside the pre-move incident drain (AM:101), before the
  MAPE stages; J-pre pairs after them (end of _run_execution).  For a launch
  detection the MAPE stages of step 1 therefore see a confirmed, UNBOUND victim
  under JOINT.  The movement timing is unchanged (5.7).  MEASURED on one uniform
  cell with a step-1 detection (A_N, seed 9601, VICTIM_SPAWN_MODE 1, CRN, 20
  steps, scratch run): dp0 and dp1 rows_uav, rows_ff, rows_vic, rows_dec,
  rows_trig and eval are IDENTICAL; J's binds equal legacy's.  How often it
  arises: launch detections occur in 5/16 (set 1) and 10/16 (set 2) uniform
  cells of the untune screen (ut2u / ut2u2) and 0/32 ring cells.  FOR PART 3: a
  cell whose dp0 run has a pre-phase assign can diverge from dp1 before J's first
  different decision; diagnose such a cell with this in mind (21.2(a)/(b)).
  PAPER: "a launch detection is dispatched after, not before, the MAPE stages of
  step 1; no effect was measured in the one cell checked".
P2-6 BFS on a flat array (GridDistances).  The dict-based search cost 1.4 ms per
  search on an idle core (design 12.2 assumed 1.0-1.8 ms); in the 90-step dp1
  smoke cell (D_N 9633) J-post calls with a contestable binding took 50-70 ms
  (J p99 69 ms - S6's limit is 50 ms).  The flat-array search is value-identical
  (3000 random grids with blocked sources and out-of-grid blocked cells: 0
  mismatches in contents, membership, get() and route_distance) and the dp1
  smoke cell re-run with it is identical in every row, eval, command, release,
  J event, ledger, binder, waiting, invariant, M8, M9 and write-off record; J
  total 1072 -> 420 ms, p99 69 -> 9 ms, max 9.4 ms.  The 50-70 ms calls were
  most probably cyclic-GC pauses triggered by the dict search's ~2500 tuple
  allocations per search (inferred, not measured).  This is 12.2's cost model
  implemented, not a design change; 15's NOT READY path ("optimised ... with
  value identity to dp1") was not needed.  PAPER: dispatch cost (M7) is
  reported for this implementation.
P2-7 M4's counterfactual (the instrument's legacy select in victim-index order
  on J's snapshot) can differ from what dp0 actually did: in the smoke cell at
  step 63 it matched J while dp0 (drain order) chose another victim.  M4 counts
  disagreement with that rule, not with the realised baseline.  Reported, not
  gated.  PAPER: say so where M4 is quoted.
P2-8 A stationary incumbent is a stalled one.  Calling J-post repeatedly without
  movement (a profiling scratch run) chains stall replacements through FRESH
  pairs only (each pair once, at most N-1 per victim): the ledger theorem at
  work, and the stall rule's intent - but note it for Part 3's diagnoses (a unit
  held in place by something other than fire is replaced after S steps if a
  fresh challenger with a clean approach qualifies).  PAPER: none beyond 6.4.
P2-9 K13 (21.2(h), 21.5): recorded risk; measured by the instrument's
  record-only M9.  No design element was added.
P2-10 Design 6.7 step 4 versus 14.6 G-B(f) (R3 finding 5) - A CONFLICT INSIDE
  THE PRE-REGISTRATION, NOT RESOLVED HERE (ruling R-A, section 9).  The SECOND
  FILL offers units released by a REPLACE to W only (6.7, implemented as
  written).  A released unit that could LATCH-FILL an unmatched latched-held
  victim (b <= 1, finite d) therefore stays free until the next J-pre, and the
  after-J-post sample counts that victim-step as ledger-allowed abandoned
  waiting - 14.6's STRUCTURAL zero.  Rare (a REPLACE and an unmatched W_L victim
  in the same frame).  T-INV's I4 latch leg follows 6.7 as written (released
  units exempt in that frame); the analyzer applies 14.6 literally and prints the
  ledger-allowed count split W / W_L, so either ruling can be applied to data
  without re-running.  PAPER: depends on the ruling.
  RULED R-A (amendment A2, dispatch_part1.txt 22.1): the second fill also
  serves W_L under the LATCH-FILL cap; I4 then holds with no released-unit
  exemption.  NOT YET BUILT at this commit - the code above still follows the
  old 6.7; the build (T-R10 with mutants tr10a-c, T-INV's exemption removed,
  T-FLIP-a's simulator) is pre-registered in 22.5 and runs on the post-audit
  main before Part 3.
P2-11 G-B(f) custody (R3 finding 4): the instrument's waiting sample excludes a
  victim whose binder is exiting, rescue_completed or on the victim's cell -
  J's own W / W_L (5.2).  14.6 says "no ACTIVE binder"; a carried victim whose
  carrier is route_blocked (the HOLD-0 repeated raise, 8.4) has no active
  binder but is in custody, and J never touches custody by design.  Excluded
  victims are listed in dp.waiting_custody.  PAPER: "abandoned waiting" counts
  victims no unit is carrying or standing on.
