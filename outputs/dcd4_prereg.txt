5. THE GATE (the maintainer's rule, verbatim, then how it is applied)
  "if dcD's never_detected on the fourth set is within 1-2 of the mode-0
   baseline AND rescued does not decrease, dcD is shippable."
  Applied to the 30 tuples, seed-matched:
     nd(d4D) - nd(d4off) <= +2   AND   rescued(d4D) - rescued(d4off) >= 0
  Both fourth-set-alone and pooled figures are reported side by side; the gate
  verdict is read on the fourth set ALONE (that is what the rule names).
  STATED NOW, NOT AFTER: the +2 is an absolute count, so it is stricter on a
  larger sample. It allowed 0.15 extra never_detected per run on the canonical
  13, 0.20 on the fresh 10, 0.11 on the rbgate 18; on 30 it allows 0.067. The
  rule is applied as written; the per-run rate is reported alongside so the
  maintainer can see how much of a verdict is sample size.
  REVERSAL CHECK. The 41 supported three directional claims: (R1) dcD rescued
  >= baseline; (R2) dcD's never_detected cost is far below single-NW dcA's;
  (R3) (dcC only, not rerun). On the fourth set R1 reverses if d4D rescued <
  d4off; R2 reverses if nd(d4D) - nd(d4off) >= nd(d4A) - nd(d4off). Either is
  reported plainly as a sixth instance of the wider-sample pattern.
  Regardless of the verdict, BASE_STATION_MODE is NOT flipped in this round.

6. DRONE STEPS IN FIRE - definitions fixed now
  The 2.1% canonical / 3.0% fresh at 8520706 (interior-hazard round) is
  VICTIM-SEARCHER steps on a burning cell / victim-searcher steps (position
  after the step against the burning set after the same step). The base-station,
  depot and dock-fix rounds instead report ALL-UAV uav_actions[2] share - the
  dock-fix report's claim that these are the same definition is wrong on role
  scope. Both are reported, each against its own reference:
    searcher-only (IH): 8520706 2.12% / 2.98%; mode-0 at HEAD 2.08% / 3.17%
    all-UAV (dc/df):    dfD 3.52% / 1.94%; dfA 3.06% / 2.41%; dfzero 1.44 / 2.01
  CONSECUTIVE: every maximal run of >= 2 consecutive steps a UAV spends on a
  burning cell, and separately every run on the SAME burning cell, split by
  base_state (flying / returning / charging) - a UAV charging in a depot whose
  block is burning sits on a burning cell by construction, and SE burns in 19
  of 20 baseline fires.

7. ZERO DEADLOCKED UAVs - the checks, fixed now
  Redefined stranding gate (_dc_arms.py --mode stranded logic): STUCK = final
  base_state "returning" with >= 10 trailing frames on one cell; UNARRIVED
  trips (arrival_step None), each classified horizon-truncated or not;
  ZERO-BATT outside the depot (old gate, kept as a column).
  Livelock (_df_evidence.py --mode livelock logic): CYCLE = a return leg comes
  back to a cell it had left, after collapsing repeats; OSCILLATION = a 10-frame
  window on <= 2 distinct cells with >= 2 cell changes.
  The brief names cell-revisit and distance-progress. The dock-fix round
  implemented revisit as CYCLE and DID NOT IMPLEMENT distance-progress at all.
  This round adds both as specified in dockfix_part1.txt 9f:
    REVISIT  = a cell visited more than twice within one return trip;
    PROGRESS = Manhattan distance to the trip's target berth fails to decrease
               over a 10-step window of a return leg (reported split inside /
               outside the target depot's footprint).
  The new checks must FIRE on the recorded deadlock (dcB east/half/808, UAV
  2500) and on dfm2ref's five, or they are not trusted.
