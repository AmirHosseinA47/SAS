2. WHERE THE NUMPY BOOL COMES FROM (the mechanism behind A, and the risk behind B / C)
================================================================================
2.1 The fire.
  - cfv.euclidean_distance returns numpy.linalg.norm(...), a numpy.float64 (common_fixed_variables.py:1002-1006).
  - distance_rate returns that float ** -2.0 (:1010-1015), so Fire.probability_of_fire's P is a numpy.float64
    whenever a neighbour lies within the radius (agents.py:53-85, the product at :81).
  - Fire.step: cell_prob = max(0.0, min(1.0, P * 0.75)) (agents.py:100-102); next_burning_state = generated <
    cell_prob (:104). Fire.advance: burning = next_burning_state (:125).
  - A comparison with a numpy.float64 is a numpy.bool_. numpy 2 names that type "bool"; it is neither the Python
    True singleton nor an int.
  - Two Python-bool cases remain:
    (a) a cell whose probability is EXACTLY 0. Python's max returns its first argument among equals, so cell_prob
        is the Python 0.0 and the draw yields Python False;
    (b) a cell clamped to 1.0. This is impossible here: P <= 1, so cell_prob <= 0.75 and min(1.0, .) never returns
        its own 1.0.
  - So EVERY cell that is burning after any spread tick holds numpy True. The census sees Python True burning only
    on steps 1-2: the seeded cell, created with the literal True (wildfire_model.py:2504 -> new_fire_agent :2509).
    In every run the first burning cell that is not Python True appears at step 3 (FIRE_SPREAD_SPEED 3), and no
    Python-True burning cell exists after step 2 (section 3.0).
  - firefighter_extinguish / burnt / the init write Python False, which is harmless at an `is True` test.
  - Since the first code commit. a4a01b4b (2026-07-27, "Add core project files") already has both
    agents.py:`is_burning() is True` and euclidean_distance via numpy.linalg.norm. A numpy bool scalar has never
    been the Python True object, in any numpy version, so the defect does not depend on numpy 2.
2.2 Every other numpy source in scope.
  - Only three modules import numpy: src_extension/knowledge/victim_search_belief.py,
    planning/fire_arrival_estimate.py and planning/searcher_targeting.py. Plus cfv (euclidean_distance).
  - Callers of euclidean_distance: local_uav_monitor.py:384 (drift), wildfire_model.py:1226 and :3508 (MR2 -
    `distance < SECURITY_DISTANCE` is a numpy bool used only in an `if`, which is correct).
  - A numpy.float64 is a float subclass and passes every isinstance(float) test.
  - What fails is a numpy BOOL, a numpy INTEGER (not an int subclass) or a numpy.float32 (not a float subclass),
    shown in outputs/_ist_demo.txt. Each arises from a comparison, a count or a reduction over numpy values.
