================================================================================
0. WHAT THIS SAYS
================================================================================
Both mechanisms are confirmed. The brief UNDERSTATES the defect on three counts,
and each correction changes what the fix has to do.

  1. The task brief says the pure-axis case is untested. IT IS TESTED.
     tests/test_base_station.py:483 test_stall_sidestep_cannot_fire_on_a_pure_
     axis_approach asserts the BROKEN behaviour deliberately, so a fix flips it
     visibly. It passes today. Fixing the steer MUST flip it - an intended flip,
     not a new failure. Section 8 says how the gate should read that.

  2. Exposure is not "1 in 92 trips". At BASE_STATION_MODE 2 it is endemic: the
     base-station round's own mode-2 arm deadlocks in 5 of the canonical 13 runs
     - 38% - permanently, 33 to 65 steps, 37-42 battery in hand. Mode 3 masks it.
     Counting both modes there are TWELVE episodes of this defect on disk, four
     of them on the canonical 13.

  3. MECHANISM 2 IS INDEPENDENTLY FATAL, and the dominant case is not the one the
     brief describes. In all five mode-2 deadlocks NOBODY STOLE THE STRANDED
     UAV'S BERTH - its berth is FREE and stays free. It is stuck because the one
     cell on its pure-axis path holds a permanently docked UAV. Fixing mechanism
     1 would not save one of them.

THE FIX. One new trigger and one new behaviour, behind one ordinal kill switch:

  THE TRIGGER, shared. rtb_stall_steps - CONSECUTIVE refused steps on this return
  leg, reset by any successful move. Derived threshold 3. Over every armed run on
  disk these episodes are 1 step (184), 2 steps (5), then NOTHING AT ALL between
  3 and 8, then 13 episodes of 9 to 65 steps, every one of them a stall the UAV
  never escapes. A one-step transit produces at most ONE refused step, so it can
  never reach 3.

  MECHANISM 1. Re-key the docking fallback from "is my berth occupied AT THIS
  INSTANT" to "has this leg stopped moving". This SUBSUMES the transient-transit
  fix rather than merely debouncing it, and it also fires in the case a
  berth-occupancy test cannot see - the mode-2 case, where the berth is free.
  The dock CELL stays exactly where it is: inside the latched depot. Section 10
  is emphatic about why it must not be widened to the doorstep.

  MECHANISM 2. When a leg has stalled and is OUTSIDE its depot, LATCH the nearest
  free cell of that depot and steer to it on EVERY STEP until inside. Then the
  ordinary steer and the re-keyed fallback take over.

Three candidate rules were replayed against the recorded deadlocks. TWO OF THEM
FAILED, and one of the two was this design's own first draft:

  R1  "when stalled, don't re-pick a direction the grid already refused"
      LIVELOCKS. And a livelocking UAV is INVISIBLE to the round's stranding
      gate, because it moves every step.
  R3  "leave the steer alone, dock after L stalls on the depot doorstep"
      terminates, but docks the UAV OUTSIDE the depot, where at mode 3 it
      recharges on open ground and its recorded base_state flips to "charging" -
      scoring clean on the stranding gate without the UAV ever coming home.
  R4  the recommended rule. Reaches the depot in both recorded failure classes,
      and in the mode-2 case reaches THE UAV'S OWN BERTH.

No new recorded field. No harness change. No instrument drift.

    def _rtb_direction(self, berth: tuple[int, int]) -> int:
        """Greedy one-step direction toward the berth, with a stall sidestep.
        ...
        """
        x, y = int(self.pos[0]), int(self.pos[1])
        dx, dy = berth[0] - x, berth[1] - y
        # move_x = [1, 0, -1, 0], move_y = [0, -1, 0, 1]
        x_dir = 0 if dx > 0 else (2 if dx < 0 else None)
        y_dir = 3 if dy > 0 else (1 if dy < 0 else None)
        if abs(dx) >= abs(dy):
            primary, secondary = x_dir, y_dir
        else:
            primary, secondary = y_dir, x_dir
        [ ~30 lines of KNOWN-DEFECT comment, quoted in 1d ]
        stalled = self.rtb_last_pos is not None and self.rtb_last_pos == (x, y)
        if stalled and secondary is not None:
            primary, secondary = secondary, primary
        if primary is not None:
            return primary
        if secondary is not None:
            return secondary
        return int(self.selected_dir)

THIS RANKING IS WHY THE DEFECT IS STRUCTURAL. Berths are ranked by DESCENDING
distance from the nearest grid edge, so they are handed out on the depot's
INTERIOR-FACING boundary - the side a returning UAV arrives from. For the corner
depot at origin (0,45) size 5 on a 50x50 grid the four UAV berths are (4,45),
(3,45), (3,46), (4,46), all on the y=45/46 rows, and the approach cell from the
grid interior is (x,44), one row OUTSIDE the footprint. A UAV whose x already
matches its berth makes its final approach straight up the y axis from a cell
where the fallback cannot fire. All twelve recorded stall episodes are at (3,44)
or (4,44). The geometry selects for the bug.

More generally: the cell before the berth differs from it in exactly ONE
coordinate, so EVERY return leg ends on a pure-axis approach. This is the
terminal condition of every trip, not a corner case.

--------------------------------------------------------------------------------
wildfire_model.py:180 uses mesa.time.SimultaneousActivation. In mesa 1.2.1 that

and _rtb_berth_blocked - an instantaneous read of that live grid - sees the NEW
position of any earlier-ordered agent. A UAV that will hold a berth for one step
is indistinguishable, at that instant, from one parked there for good.

================================================================================
4. WHAT THE FALLBACK PROTECTS - ESTABLISHED, NOT ASSUMED
================================================================================
This project has three times found a guard that looked like a defect and was
load-bearing, so the fallback was tested before being touched.

THE CLAIM IN THE COMMENT: "a UAV that is not returning can be parked on someone
else's berth, and without this fallback the returning UAV would oscillate against
not_UAV_adjacent until the blocker happened to move."

IS THE PREMISE REAL? Yes. Section 3b records a 14-step episode whose occupier was
idle when it began (dcA south/half/808), and section 2d records a released UAV
holding a berth from step 216 to the horizon because it was head-on with another
unit. A non-returning UAV genuinely can sit on someone's berth and genuinely can
be unable to leave.

IS THE CONSEQUENCE REAL? Yes, and worse than "oscillate". The blocker may be
permanently immovable - at mode 2 a docked UAV never releases - so "wait for the
blocker to move" is not a terminating strategy at all.

THE GUARANTEE THE FALLBACK SUPPLIES, stated precisely:

    A return leg that has reached ANY cell of its target depot terminates in a
    bounded number of steps, without depending on any other agent's future
    behaviour.

That is the property to preserve. Note what it does NOT say: it says nothing
about a UAV that has not reached the depot. That silence is mechanism 2.

DOES RE-KEYING PRESERVE IT? Yes, and it strengthens it. Today the trigger is a
property of ANOTHER AGENT ("is a UAV on my berth"). Re-keyed, it is a property of
THIS UAV'S OWN PROGRESS ("have I stopped moving"), which is exactly the kind of
predicate a termination argument wants: it cannot be starved by another agent's
behaviour, and it is true in strictly more of the cases that matter - including
section 3d, where the berth is free and the old trigger is silent forever.

WHAT WOULD NOT PRESERVE IT: removing the fallback; conditioning on the occupier
being "docked" (at mode 2 a pinned RELEASED UAV is not docked and is still
immovable); or waiting for the blocker.


================================================================================
5. THE RECOVERY - AND THE TWO RULES THAT FAILED, ONE OF THEM MINE
================================================================================
Taken before mechanism 1 because it is the harder half and it constrains the other.

outputs/_df_sandbox.py replays the deadlock under candidate rules. FOR THE MODE-2
SCENARIO THE REPLAY IS EXACT, NOT A BOUND: the other three UAVs are docked and
BASE_STATION_MODE 2 has no release path at all (agents.py:503 gates release on
mode >= 3), so they provably never move again and the stalled UAV is alone in a
static world. The mode-3 scenario freezes the blockers by hand and is a worst
case: at mode 3 they would eventually leave, so a rule that terminates here
terminates there too.

--------------------------------------------------------------------------------
5a. R1 - "when stalled, don't re-pick a direction the grid already refused"
--------------------------------------------------------------------------------
The obvious minimal fix, and the first thing anyone proposes. IT LIVELOCKS.

  R1, mode-2 scenario, UAV 2502 at (3,44) berth (3,46):
    step 0: at (3,44)  +y -> (3,45)  BLOCKED
    step 1: at (3,44)  +x -> (4,44)  move
    step 2: at (4,44)  +y -> (4,45)  BLOCKED
    step 3: at (4,44)  -x -> (3,44)  move
    step 4: at (3,44)  +y -> (3,45)  BLOCKED
    ... forever; 20 revisits of the same cell in 40 steps

WHY, and the reason generalises: the escape step is taken while STALLED, but the
step after it is taken while NOT stalled, and the unstalled greedy is
unconstrained - it walks straight back. A rule whose memory is one step cannot fix
this, because the reversal happens on the step where the rule is not looking.

AND IT IS WORSE THAN IT LOOKS. A livelocking UAV MOVES on most steps, so the
round's positional stranding gate - "unchanged position for N consecutive steps"
- SCORES IT ZERO. A fix that turned the freezes into livelocks would have read as
a clean sweep. It is also more expensive than the freeze it replaces: 2 moves and
1 stall per 3 steps is (2*0.3 + 0.1)/3 = 0.233 battery/step against 0.100 for a
frozen leg, and it puts a MOVING UAV onto cells a frozen one never touches, so it
is a battery and an exposure regression at the same time. Section 9 adds a gate
for this.

CONCLUSION: SOME LATCHED STATE IS UNAVOIDABLE. That is forced, not preferred.

--------------------------------------------------------------------------------
5b. R3 - "leave the steer alone; dock after L stalls on the depot doorstep"
--------------------------------------------------------------------------------
A genuinely attractive alternative, and it was the adversarial review's own
recommendation. Keep _rtb_direction exactly as it is - it is distance-monotone,
every successful move reduces the distance to the berth by exactly 1, and that
monotonicity is what makes a consecutive-stall counter a valid termination
variant - and put the terminator one level up, allowing the dock cell to be the
depot OR its one-cell doorstep.

It terminates, cheaply, with a short proof. IT IS REJECTED ANYWAY, on this:

    _update_battery_after_step (agents.py:312-314) gates the recharge on
    self.rtb_docked ALONE, with NO POSITIONAL TEST. And the harness's _base_state
    (outputs/_ffr_harness.py:422-432) reports "docked"/"charging" from the same
    flag, also with no positional test.

So a doorstep dock at mode 3 REFUELS A UAV ON OPEN GROUND, one cell outside the
depot, and flips its recorded base_state from "returning" to "charging". The
round's positional stranding gate only counts UAVs whose final state is
"returning". A doorstep dock therefore CLEARS THE GATE WITHOUT THE UAV EVER
COMING HOME - it changes the label on the failure rather than the failure. This
campaign has twice been burned by an instrument reading clean while nothing
improved; this would be a third, and self-inflicted.

  R3 replayed, both scenarios:
    modethree: dock at (4,44) after 3 stalled steps - on the DOORSTEP, OUTSIDE
    modetwo:   dock at (3,44) after 3 stalled steps - on the DOORSTEP, OUTSIDE

Both of those are the exact cells the stranding gate currently flags. The rule
converts twelve flagged stalls into twelve unflagged open-ground recharges.

The half of R3 that is RIGHT and is adopted: the consecutive-stall trigger, and
leaving _rtb_direction's monotonicity intact. What is rejected is only the
widened dock location.

--------------------------------------------------------------------------------
5c. R4, RECOMMENDED - latch a free depot cell and steer to it STICKILY
--------------------------------------------------------------------------------
    WHEN a return leg has stalled and the UAV is NOT inside its target depot,
    LATCH the nearest free cell of that depot and steer to that cell INSTEAD of
    the berth ON EVERY STEP, until the UAV is inside the depot. Then drop the
    latch; the ordinary steer and the re-keyed fallback take over.

THE WORD "STICKILY" IS THE WHOLE FIX, AND MY FIRST DRAFT GOT IT WRONG. The draft
engaged the recovery only on the step where the UAV was stalled and let the
shipped greedy run otherwise. That is R1 with extra steps: the escape moves the
UAV, so the next step it is not stalled, the greedy toward the berth runs, and it
walks back. The latch must own the steer on EVERY step of the recovery, not just
the stalled ones. The adversarial review found this; the replay confirmed it.

A SECOND SUBTLETY, also found by replay: THE STALL IS RELATIVE TO A TARGET. The
shipped swap exists to break a deadlock against the cell we were refused moving
toward. Carrying `stalled=True` into the first steer toward a NEW latched target
makes it swap axes it has never been refused on - and in the (4,44) case it swaps
straight onto the blocked one. The stall flag is only passed through when the
target is the same one we stalled against.

WHY IT CANNOT PING-PONG. While the latch is set the target is a FIXED, FREE cell
that does not move, and the steer toward it is the unmodified, distance-monotone
_rtb_direction: every successful move reduces the distance to that cell by
exactly 1. The reversal that defeats R1 cannot occur, because after the escape
step the target is still the latched cell, not the berth. The latch is also the
codebase's own device for exactly this hazard - agents.py:258-261 already records
that an unlatched target "would flip the heading with it and the UAV never
arrives", which is why the TRIP target is latched at the trigger.

WHY IT TERMINATES. Distance to the latched cell strictly decreases on every
successful move, and the cell is inside the depot; on arrival the latch drops and
section 4's guarantee - now keyed on the stall witness - takes over. THE RECOVERY
DOES NOT HAVE TO REACH THE BERTH. It only has to reach the depot.

REPLAYED, both recorded failure classes:

  MODE 2 - the berth is FREE, the path cell is permanently blocked. EXACT replay:
    step 0: at (3,44)  +y -> (3,45)  BLOCKED     <- stall witnessed
    step 1: at (3,44)  -x -> (2,44)  move        <- latched (2,45), routing
    step 2: at (2,44)  +y -> (2,45)  move        <- inside the depot; latch drops
    step 3: at (2,45)  +x -> (3,45)  BLOCKED     <- steering to the berth again
    step 4: at (2,45)  +y -> (2,46)  move        <- the EXISTING two-axis swap
    step 5: at (2,46)  +x -> (3,46)  move
    step 6: DOCKED AT ITS OWN BERTH (3,46)
  Against 33-65 steps of permanent deadlock at HEAD, and against R3's open-ground
  dock at (3,44).

  MODE 3 - the berth ITSELF is taken by a fallback-docked UAV, blockers frozen:
    step 0: at (4,44)  +y -> (4,45)  BLOCKED
    step 1: at (4,44)  -x -> (3,44)  move
    step 2: at (3,44)  -x -> (2,44)  move
    step 3: at (2,44)  +y -> (2,45)  move        <- inside the depot
    step 4: at (2,45)  +x -> (3,45)  BLOCKED
    step 5: at (2,45)  +x -> (3,45)  BLOCKED
    step 6: dock at (2,45) after 3 stalled steps - INSIDE the depot
  No routing can reach the berth here, and the re-keyed terminator closes it - on
  a PLAIN depot cell, displacing nobody. The two halves composing.

Note what the mode-2 replay shows about scope: INSIDE the depot nothing new is
needed. The shipped two-axis swap does the work at step 4, because inside the
depot an approach is generally not pure-axis. The recovery is scoped to outside
the depot only, and an earlier draft that let it keep re-latching inside was
caught by the replay wandering back out.

NEW METHOD, agents.py beside the other _rtb_* helpers:

    def _rtb_recovery_berth(self, here):
        """The latched depot cell to steer to instead of the berth, or None.

        A leg stalled OUTSIDE its depot has no escape at HEAD: the sidestep in
        _rtb_direction is structurally dead on a pure-axis approach, and the
        docking fallback is scoped to the depot interior. Measured: 12 episodes,
        5 of them permanent. See outputs/dockfix_part1.txt section 3.

        Returns None - and the caller then steers to the berth exactly as at HEAD
        - when the fix is off, when the UAV is already inside its target depot,
        when the leg has not stalled, or when there is no grid to consult.
        """
        if base_station_dock_fix() < 2:
            return None
        if self._rtb_inside_depot(here):
            self.rtb_recovery_cell = None
            return None
        model = getattr(self, "model", None)
        grid = getattr(model, "grid", None)
        station = getattr(model, "base_station", None)
        if grid is None or not station:
            return None

        def free(cell):
            return not grid.out_of_bounds(cell) and self.not_UAV_adjacent(cell)

        target = self.rtb_recovery_cell
        # Re-latch only when there is no latch, it has been reached, or it has
        # become occupied - NOT every step, or the target flips and the heading
        # flips with it.
        if self.rtb_stall_steps >= base_station_return_stall_limit() and (
                target is None or target == here or not free(target)):
            depot = 0 if self.rtb_target_depot is None else int(self.rtb_target_depot)
            depots = station.get("depots") or ()
            cells = depots[depot]["cells"] if depot < len(depots) else station["cells"]
            best = None
            for cell in sorted(cells):        # ties break on (x, y): deterministic
                if cell == here or not free(cell):
                    continue
                d = abs(cell[0] - here[0]) + abs(cell[1] - here[1])
                if best is None or d < best[0]:
                    best = (d, cell)
            target = best[1] if best else None
            self.rtb_recovery_cell = target
        return target

CALL SITE, agents.py:565-573. The stall witness is recorded for BOTH mechanisms,
above the mechanism gate; the recovery only steers under mechanism 2, where the
steer is ours to set:

        self.rtb_return_steps += 1
        if base_station_return_mechanism() != 2:
            # Planner route: the executor already committed a direction from the
            # base waypoint. Overriding it here would mask the mechanism entirely.
            return
        recovery = self._rtb_recovery_berth(here)
        if recovery is not None:
            # Steer to the latched cell, not the berth. The stall flag is only
            # carried over when the target is unchanged - the shipped swap breaks
            # a deadlock against the cell we were refused on, and applying it to a
            # target we have never been refused against picks the wrong axis.
            same = (self.rtb_recovery_stalled
                    and self.rtb_last_pos is not None and self.rtb_last_pos == here)
            saved, self.rtb_last_pos = self.rtb_last_pos, (here if same else None)
            direction = self._rtb_direction(recovery)
            self.rtb_last_pos = saved
            self.rtb_recovery_stalled = True
        else:
            direction = self._rtb_direction(berth)
            self.rtb_recovery_stalled = False
        self.rtb_last_pos = (int(self.pos[0]), int(self.pos[1]))
        self.selected_dir = direction
        self.execution_direction_applied = True
        self.execution_action = "rtb_return"

  (The save/restore of rtb_last_pos keeps _rtb_direction a pure function while

AND the latch and the counter are cleared wherever trip state is cleared: at the

================================================================================
6. MECHANISM 1 - RE-KEY THE FALLBACK, DO NOT DEBOUNCE IT
================================================================================
The brief offers (a) wait a step / check whether the occupier is transiting, and
(b) reversible re-assignment. Both are rejected, and so is the debounce that was
this design's own first answer.

WHY NOT A DEBOUNCE of the berth-occupancy test - "require the berth to have been
blocked for K consecutive steps". It fixes the transient steal, and the data
supports a threshold. But section 3d kills it: IN ALL FIVE MODE-2 DEADLOCKS THE
BERTH IS FREE. A predicate about the berth is silent forever in exactly the cases
that dominate. Debouncing a predicate that asks the wrong question makes it ask
the wrong question more slowly.

WHY NOT "is the occupier transiting or docking". A UAV in transit to its own
berth is rtb_active and looks exactly like one about to dock; and the blocker
that matters at mode 2 is neither - it is a DOCKED unit that will never move, or
a RELEASED one that is pinned (section 2d).

WHY NOT (b), reversible re-assignment. It needs the displaced unit to notice and
reclaim, which is a claim/release protocol - the thing wildfire_model.py:671-673
says the distinct-berth design exists to avoid - and it does nothing for the
mode-2 deadlocks, where no berth was ever stolen.

WHAT IS DONE INSTEAD. Re-key the trigger to the UAV's OWN PROGRESS. The location
predicate is UNCHANGED - the dock cell must still be inside the latched depot.

THE REPLACEMENT, agents.py:553-555, with the stall witness recorded just above:

        # THE STALL WITNESS. rtb_last_pos is this leg's position at the previous
        # step, so `== here` means last step's move was refused. Any successful
        # move resets the count, so a leg that is making progress starts over and
        # blocks scattered earlier in the trip cannot spend the budget.
        if base_station_dock_fix() >= 1:
            if self.rtb_last_pos is not None and self.rtb_last_pos == here:
                self.rtb_stall_steps += 1
            else:
                self.rtb_stall_steps = 0

        # Dock at the assigned berth, or - once this leg has provably STOPPED
        # MOVING - on the depot cell it is standing on.
        #
        # THE FALLBACK IS KEPT. Without it a returning UAV whose approach is
        # blocked has no recovery at all, and the blocker can be permanently
        # immovable: at mode 2 the release branch above is unreachable, so every
        # dock is forever. There is a recorded configuration (dcA south/half/808)
        # in which deleting this block deadlocks two UAVs to the horizon.
        #
        # WHAT WAS WRONG WITH IT WAS THE TRIGGER, NOT THE FALLBACK. It fired on an
        # INSTANT of occupancy, and all UAV work runs in advance() where
        # grid.move_agent mutates the live grid mid-sweep, so a ONE-STEP TRANSIT
        # by an earlier-ordered UAV was enough to re-assign a berth permanently.
        # It was also SILENT where it was most needed: it asked "is my berth
        # taken", so a UAV boxed in with a FREE berth never fired it at all -
        # which is every one of the five mode-2 strandings.
        #
        # RE-KEYED to BASE_STATION_RETURN_STALL_LIMIT consecutive refused steps: a
        # property of this UAV's own progress and of no other agent's future
        # behaviour, which is the guarantee this block exists to provide. A
        # one-step transit produces at most ONE refused step and so cannot reach
        # the limit by construction. Measured: refusal runs are 1 step (184), 2
        # steps (5), then NOTHING until 9, and all 13 episodes of 9+ are stalls
        # the UAV never escapes.
        #
        # THE DOCK CELL IS DELIBERATELY NOT WIDENED BEYOND THE DEPOT. Recharge is
        # gated on rtb_docked alone with no positional test (:312), and the
        # harness reports base_state from the same flag, so a dock outside the
        # footprint would refuel a UAV that never came home AND relabel it from
        # "returning" to "charging" - clearing the stranding gate without
        # improving anything. See outputs/dockfix_part1.txt section 5b.
        docking = here == berth
        if not docking and self._rtb_inside_depot(here):
            if base_station_dock_fix() >= 1:
                docking = self.rtb_stall_steps >= base_station_return_stall_limit()
            else:
                docking = self._rtb_berth_blocked(berth)

path. It is KEPT, because it is the off-path predicate and because the tests use
it; it is not dead code while the kill switch exists.

--------------------------------------------------------------------------------
7a. the switch
--------------------------------------------------------------------------------
An ordinal ladder, like BASE_STATION_MODE, so the two halves can be ATTRIBUTED

  common_fixed_variables.py

      0  off. Every path behaves exactly as at 9f77178. THE KILL SWITCH.
      1  + the docking fallback is re-keyed to the stall witness (section 6).
      2  + a leg stalled outside its depot gets the latched recovery (section 5c).

  agents.py, beside the other accessors at :667-780

    def base_station_dock_fix() -> int:
        """0 off (kill switch) / 1 re-keyed fallback / 2 + stall recovery."""
        try:
            return max(0, min(2, int(getattr(cfv, "BASE_STATION_DOCK_FIX", 2))))
        except (TypeError, ValueError):
            return 2

    def base_station_return_stall_limit() -> int:
        """Consecutive refused steps before a return leg counts as stalled."""
        try:
            return max(1, int(getattr(cfv, "BASE_STATION_RETURN_STALL_LIMIT", 3)))
        except (TypeError, ValueError):
            return 3

DEFAULT ON, deliberately, and it costs nothing: at BASE_STATION_MODE 0 - the
shipped default - _apply_return_to_base returns at its first branch and NOTHING
in this change is reachable. The shipped configuration is untouched at any value
of the switch. Defaulting OFF would mean the next round that flips the mode
inherits a known deadlock, which is the situation this round exists to end. If
you would rather ship OFF, say so - it is a one-character change and the
measurement plan is unaffected.

--------------------------------------------------------------------------------
7b. why byte-identity holds with the switch off
--------------------------------------------------------------------------------
  - _rtb_direction is NOT MODIFIED except for its comment.
  - _rtb_recovery_berth returns None on its first branch when the switch is off,
    before touching any state, and the caller then takes the HEAD path verbatim.
  - The docking block takes the `else: docking = self._rtb_berth_blocked(berth)`
    path, which is the HEAD expression, called the same number of times.
  - rtb_stall_steps, rtb_recovery_cell and rtb_recovery_stalled are written only
    under a base_station_dock_fix() >= 1 guard or inside the recovery branch, so
    with the switch off they hold their initial values for the whole run.
  - The accessors are pure reads of cfv with no side effects, so call ORDER is
    unchanged.
  - No RNG is consumed, no agent added, no unique_agents_id shifted.

10. RISKS, AND WHAT IS NOT BEING FIXED
================================================================================
  1. THE RECOVERY IS NOT A PATHFINDER, and this is the honest limit. Termination
     is guaranteed while the latched cell stays free and reachable by monotone
     greedy steps. If the approach to the LATCHED cell is itself pure-axis and
     blocked, the UAV stalls again and re-latches to a different free cell; with
     at most NUM_AGENTS-1 other UAVs and 25 depot cells there is always another,
     but "it will always find one" is a property of this configuration, not a
     theorem about the rule. A depot packed to capacity is the case to watch. 9f
     is the gate that would catch it going wrong, and it is the reason 9f exists.

  2. THE FIX MOVES MODE 2 AND MODE 3 RESULTS. It must - it changes where UAVs go.
     Mode 0, the shipped default, is untouched, and 9a proves it.

  3. L = 3 IS DERIVED FROM ONE GEOMETRY over 154 runs. The 3-to-8 gap is clean but
     it is one campaign; a different depot size or agent count could populate it.
     BASE_STATION_RETURN_STALL_LIMIT is a constant precisely so this is adjustable
     without a code change, and section 4's guarantee holds for ANY finite L, so a
     wrong L costs latency, not correctness.

  4. FALLBACK DOCKS WILL NOT GO TO ZERO, and should not. 22 of 34 land on plain
     depot cells and are harmless. The gate is stranding, not dock count.

  5. NOT FIXED, deliberately out of scope: A RELEASED UAV IS NOT OBLIGED TO LEAVE
     ITS BERTH (section 2d). 2502 held (4,45) from step 216 to the horizon because
     it was head-on with 2503 in the ORDINARY movement layer, not in the RTB code.
     Fixing that means touching not_UAV_adjacent or the planner - a different
     blast radius and a different round. This fix removes the usual CAUSE of that
