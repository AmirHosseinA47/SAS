1. WHAT CHANGED SINCE THE FIRST SCREEN (two switches, both SHIP 1 and act ONLY with SEARCHER_UNTUNED = 1;
   each off only on an exact 0; with SEARCHER_UNTUNED = 0 the program is unchanged - section 2)
1.1 SEARCHER_END_RECALL (ruling 1, option B). When the honest count (briefing - detected) is 0 a victim
    searcher ends its search: UAV._apply_return_to_base starts a return at once (the battery trigger and the
    searcher return delay are bypassed), the leg is steered and docked by the existing free-cell docking, and
    a docked searcher is not released while the count is 0 (the count never rises in this simulator, so a
    recalled searcher stays docked to the horizon). The trip's rtb_log entry carries "recall": True.
    EVERY STRATEGY: the recall sits in the first statement of UAV.advance, the last writer of the direction,
    so it overrides the current chain, every SEARCHER_TARGETING arm and the Bayes arms' R-1 least-observed
    continuation (the targeting post-pass already skips a searcher on a return leg or docked).
    *** THIS CHANGES THE BAYESIAN ARMS' POST-DETECTION BEHAVIOUR, after the fix3b re-screen and before any
    measurement run: once every victim is detected a Bayes arm no longer continues with the least-observed
    rule - its searchers return and dock. WHY: so every arm ends its search the same way, and post-detection
    measures (exposure, oscillation) are not confounded by different end-of-search behaviour. It applies to a
    Bayes arm run with SEARCHER_UNTUNED = 1 (the measurement round must run every arm that way). ***
    Verified at SEARCHER_TARGETING 3 (ut2bf, ring set 1): 13 of 28 searchers recalled (all in runs where
    every victim was found), every one docked, 0 oscillation episodes, 0 runs that never finish.
1.2 FF_RELEASE_DETECTED_ONLY (ruling 3). The firefighter release reads only DETECTED victims. Exactly these
    reads change (wildfire_model.py):
      R1 _revalidate_route_blocked_firefighters, the live victim_cells loop: an undetected victim's marker
         status, managed state and TRUE position are no longer read;
      R2 its stale clear gate: "no victim needs rescue" -> "no DETECTED victim needs rescue";
      R3 _release_other_claimants' release relabel (work_left): detected victims only.
    _any_victim_needs_rescue gained detected_only (default False = unchanged).
1.3 Ruling 2: the non-coverage livelock is NOT fixed; it is on the cleanup list (section 8). Ruling 4: tie-break
    orders unchanged. Ruling 5: the pinned team in the tests stays.
1.4 TESTS: tests/test_searcher_untuned.py, 71 tests (17 new): both switches' ship/act/off rule; recall for every
