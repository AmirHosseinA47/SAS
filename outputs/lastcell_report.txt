1. WHAT WAS IMPLEMENTED
================================================================================

applied by outputs/_lc_patch.py (--check / --apply / --revert, binary mode,
idempotent, CRLF-preserving - same shape as the idle-retreat round's

  agents.py:902, `_retreat_candidates`.  The existing `return candidates`
  gains a terminal fallback in front of it:

    if not candidates and last_cell is not None and current_dist == 0:
        # The unit is standing on a burning cell and every neighbour it
        # could still step to was ruled out by the anti-oscillation
        # memory. That memory exists to stop a unit ping-ponging between
        # two free cells, and it cannot serve that purpose here: the cell
        # being vacated is on fire, so the fire test above - which comes
        # first and so outranks it - refuses the step back anyway until
        # that cell burns out. Re-run the same chain without it, so
        # `last_cell` is considered only when nothing else survived and
        # every other filter, the leash included, still applies to it.
        return self._retreat_candidates(
            cell, origin, None, fire_cells, current_dist
        )
    return candidates

              ff_unit_0  |43-25| + |20-48| = 46

          availability filter has no reachability test, so a ONE-CELL margin
          hands the victim to ff_unit_0.  It never gets there and is
          unassigned at s183.  ff_unit_1 is left idle from s75 and never
          re-tasked.  The victim dies.

  THIS IS VERDICT C OF ffdeath_investigation.txt, RE-CONFIRMED.  It lives in
  `select_rescue_assignment` in wildfire_model.py, which this round is
  explicitly forbidden to touch, and the unassign-inflow round closed it out
  as "nothing to flag" on its own sample where no dispatch had a dead route.
  Putting a live unit back into the pool exposed it.

  HOW FAR I PUSH THAT CAUSAL CLAIM: to the dispatch, and no further.  The
  tiebreak is exact and reproducible - 46 against 47, read out of the trace.
  What follows it is 86 steps of transit in a chaotic spread model, so
  "ff_unit_1 would have completed the rescue had it been chosen" is only
  supported by the fact that in stock it did.  The honest statement is that
  the fix cost a rescue on this seed through a known upstream defect, on a
  one-cell margin, and that a different tiebreak would likely not have.

9. WHAT THIS CHANGE IS WORTH, STATED PLAINLY
================================================================================
  * THE MECHANISM IS CERTAIN, not statistical.  A unit standing on a burning
    cell whose only exit was refused for anti-oscillation reasons now takes
    that exit.  It fires 4 times in 23 runs and each firing was read
    individually.  The equivalence check makes that a property of the shipped
    code, not of a monkeypatch.
  * THE MAGNITUDE IS A 23-RUN ESTIMATE and should not be quoted precisely.
    Two firefighters saved, one rescue lost.  On the 13-run sample alone it
    is one saved and one lost.
  * THE CONDITION IS PRINCIPLED RATHER THAN TUNED.  cur_dist == 0 is the
    exact case in which the fire filter already forbids the step the guard
    forbids, so suspending the guard there removes nothing.  The two rejected
    variants both fail for reasons predicted from that argument: (a) lets
    `last_cell` win a competition it should not enter and killed a unit on
    E/half 202; (c) drops the gate and produces reversals at 22% per
    re-admission.
  * WHAT IT DOES NOT DO: it does not help the four unassign-inflow cases
    (cur_dist == 1, and already moved by `_move_toward` in the same step), it
    does not help the C3 leash death, and it does nothing for an enclosed
    unit - 43 of the 61 empty-candidate scans on the 13-run sample have zero
    free neighbours and no filter is implicated at all.
  * THE LARGER LEVER IS STILL UPSTREAM.  The one regression this round
    produced was not caused by the retreat logic; it was caused by a 1-cell
    Manhattan tiebreak with no reachability test deciding which unit chases a
    victim across 46 cells.  That is where the next real win is, and it is in
    wildfire_model.py.
