WHAT WAS WRONG (Part 1 summary; full analysis in lane_clamp_part1.txt)
------------------------------------------------------------------------------
_finalize_coverage_target is lane-unaware and operates purely on global grid
coordinates. Its two overrides sit on exactly the axis the lane partitions:

  y-commit clamp   east/west wind  -> lane axis "y"
  x-sweep clamp    north/south wind -> lane axis "x"

The lane itself is what latches the override. For a lower y-lane [0..24] with
global y_max=49:

  SET      _coverage_y_lower_camping compares max(recent_y) against the GLOBAL
           half split + margin = 31. A searcher confined to y<=24 satisfies
           that unconditionally, forever. The "camping detector" is detecting
           the lane, not a pathology.
  EMIT     ty = max(y_max - 4, ty) = 45, i.e. 21 cells outside the lane.
  RELEASE  requires ay >= y_max - 6 = 43, which the lane hard filter at :3431
           and :3604 makes unreachable. The commit never clears.

Re-verifying this independently turned up something the original diagnosis
missed, and it is the reason approach (A) was rejected. The latched commit is
read in the candidate loop too, where three filters compose:

    if not _lane_allows_cell(lane, cx, cy):          continue   # cy <= 24
    if commit == "north" and cy < upper_y_min:       continue   # cy >= 25
    if y_force_min is not None and cy < y_force_min: continue   # cy >= 45

cy<=24 AND cy>=45 is unsatisfiable: the candidate set is EMPTY, not merely
degraded. best_point stays None and control falls to the :3505 fallback, which
synthesises the GRID CENTRE with no reference to the lane. That is the true
source of the measured 73.5% out-of-lane emissions at y=45, and of the 35/119
identical-target steps (the upper-lane searcher reaches y=45 legally inside
[25,49]; the lower-lane searcher arrives at the same row via the centre
fallback - two code paths converging on one cell).

APPROACH CHOSEN: (B) SUPPRESS, applied AT THE SOURCE.
(A) "clamp the clamp" would clip the emitted y but leaves the loop's own
commit / y_force_min filters untouched, so the candidate set stays empty and
the searcher stays on the degenerate centre fallback for the entire run. (A)
would raise the compliance metric while leaving the primary failure path fully
intact - passing the gate by breaking the thing the gate exists to protect.
(B) is also justified on redundancy: inside a lane the searcher is already
bounded on the clamp's axis, and within-lane anti-camping is already handled by
_corridor_diversity_failure, _uncovered_region_bonus and the saturated-cell
decay, all of which are per-uav and relative to the searcher's OWN visited span
rather than to global grid coordinates - i.e. lane-safe by construction.

THE CHANGE
------------------------------------------------------------------------------
1. Per-searcher lane axis recorded in wind_state (already keyed by uav_id):
   _set_active_lane_axis / _active_lane_axis, set where the lane is already
   computed (:3460, :3634) and at the entry of _compute_wind_aware_search_target
   (:3747).
2. _update_coverage_y_commit: when the lane axis is "y", clear the commit and
   return. This neutralises the y-commit at ALL FOUR of its read sites at once
   (finalize, both candidate loops, the corridor_fail clamps) so the two
   representations can never disagree.
3. _finalize_coverage_target: skip the west/east sweep pulls when the lane axis
   is "x". The unconditional interior bound
   tx = max(safe_x_min, min(safe_x_max, tx)) is NOT touched - that is a grid
   safety clamp, not the sweep override.

The suppression is precisely axis-scoped: for a y-lane only the y-commit is
suppressed and the x-sweep stays fully active, and vice versa. This is visible
in the probes below - under north wind (x-lane) the y_commit histogram still
latches north/south normally, because y is the free axis there.

NOT TOUCHED, as required: _searcher_crosswind_lane, _lane_allows_cell, the
x-clamp reachability fix, and the fix14 target-hold mechanism.

NOTHING WAS TUNED
------------------------------------------------------------------------------
No constant was adjusted and no threshold was moved to reach any gate. The
change is a pair of conditional suppressions plus the bookkeeping to know which
axis a lane occupies. Approach (B) was selected in Part 1 on structural grounds
BEFORE the post-fix matrix was run, and was not revisited after seeing results.

One deliberate decision not to change more: a residual path was identified
where _finalize_coverage_target applies a stale coverage_y_commit when
unresolved_victim_count == 0 (the update at :1155 is guarded, the application
at :1159 is not). It was left alone because it is unreachable, not because it
was overlooked. _update_coverage_y_commit is the only writer of that key, and
it is called unconditionally from _sync_wind_search_streaks (:1645) on every
step where the searcher has a position - which in
_compute_wind_aware_search_target runs at :3762, after the axis is set at :3747
and before every _finalize_coverage_target call (:3845, :3884, :4068). The only
earlier return is the "if not fire_cells: return None" guard. Adding a
redundant gate there would have enlarged the surface needing re-validation for
no behavioural gain.
