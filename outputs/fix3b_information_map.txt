CORRECTIONS
C1 (M1, environment-monitor stamps and fire belief).
- The monitor reports a Fire cell as SMOKE when its smoke is active, and as FIRE only otherwise (the `elif`, environment_monitor.py:29-31).
- So a burning cell under active smoke is stamped SMOKE_OBSCURED. Its fire-belief probability is not set to 1.0; mark_smoke_obscured only lowers confidence (fire_runtime_model.py:152-166).
- Cells already declared that step by a UAV are skipped (wildfire_model.py:1351, :1384).
- The class (A3) is unchanged.

C2 (M2, the RW row "Detected-but-unhandled victim", classed S).
- The gate is _victim_handled_for_uav_target. It reads managed flags and marker status, which is P.
- That check runs before EVERY fix3b hook in every arm (uav_executor.py:1061-1062 comes before :1356).
- I infer it is inert, because confirmed is only ever set True (writers: wildfire_model.py:1461, :4926; rescue_executor.py:568). Reclassified as P (inert) for all arms.

C3 (M2, the RW row "N, detection events, belief", classed B). These are not read by RW. Detection events are S. Table cell: '-'.

C4 (M2's claim that R-1 closes P exposure once all victims are detected). This is overstated.
- After N_unf = 0 the arm runs the LO rule. LO can still return None: no reachable, battery-feasible, not cooled-down tile farther than Manhattan 2. That sets the R=10 hold with no delivery.
- The on-hazard skip, the route-field-inactive skip, return legs and the fail-safe pre-dispatch call also deliver nothing.
- On all of these steps the current chain steers and reads _count_unresolved_victims (searcher_targeting.py:173-178, :331-351).
- So R-1 removes the systematic hand-back, but not every hand-back.

C5 (detection rule). M1 classed it B, M2 classed it S. Harmonised: the rule (Euclidean distance <= 8, true UAV cell to true marker cell) is B as the sensor spec. Its outputs (detection events) are S.

OMISSIONS FOUND
O1 (CUR and shared; P). Mission goals use a second P count.
- _build_mission_goal_runtime_context counts alive_victims_remaining over every marker that is not dead, rescued or unreachable. It includes undetected victims and drops unseen deaths (wildfire_model.py:3691-3704, :3603-3650).
- That count sets the mission phase ('evacuation' at fire severity >= 0.65) and prioritize_victim_search (mission_goal_model.py:198-235).
- prioritize_victim_search adds +0.12 confidence to the wind-aware search option (local_adaptation_generator.py:1892-1899).
- M1 missed this entirely. Its effect on fix3b-owned steps is inferred to be nil.

O2 (hazard-gate and BFS smoke source; A3 with an S component). Strict smoke is active Fire-agent smoke plus the visibility SMOKE_OBSCURED labels.
- The labels are sticky: staleness never ages them (visibility_model.py:175, :196). They persist until a UAV footprint overwrites the cell.
- The executor's read of visibility_model.smoke_obscured_cells is DEAD, because the set lives on .state (uav_executor.py:2004, :2872 against visibility_model.py:32-37, :48-66). The status-map read carries the same content.
- _fix3b_true_fire reads .state correctly.

O3 (LO mask). LO ages come from belief.last_cover, which uses the Euclidean-8 disc of every UAV. LO does not use the visibility model's 17x17 coverage map, so the square/disc mismatch does not reach LO. The searchable mask is burning cells plus _fix3b_true_fire smoke, including the sticky labels.

O4 (eligibility). A searcher is eligible only if A1-R applies (route field on, retreat range 99, near field on) and its own cell has strict hazard level 0 (searcher_targeting.py:173-178).

O5 (N). The default N is NUM_VICTIMS = 5 (common_fixed_variables.py:80). lambda = n_unfound * the alive mass p. A detected victim stays counted after it dies.

O6 (spawn). The uniform spawn draws with replacement. The fire is created at :205, before both the spawn (:293) and the prior (:406), so H0 equals the generating distribution exactly.

O7 (sector bounds). None of the fix3b strategies uses sectors. Their only bound is the edge band of 4 (the tile layout and the stride-2 candidate lattice).

O8 (wind in the flee model). Verified absent. The flee model uses only the Euclidean distance to true burning cells.

PRIVILEGED (P) INFORMATION BY STRATEGY
CUR:
(1) _count_unresolved_victims. It counts undetected victims and drops unseen deaths. Through it:
- it switches coverage mode (always True when > 0);
- it sets coverage priority 0.9, the hybrid wind weight 0.15*0.35, and the never-seen and uncovered bonuses;
- it sets the y-commit and the path-planner coverage escape;
- it gates the post-rescue burst.
(2) The mission-goal alive_victims_remaining count: the phase and the +0.12 confidence on the search option (NEW).
(3) The managed handled flags in the planner and executor victim-known branches (inert: confirmed is set at first detection).
(4) Implicitly, the fixed-ring spawn, through constants tuned on it.

LO: no direct P read. Indirect exposure:
- the inert P handled-check runs before the hook every step;
- the current chain reads the P count on fallback, R-hold, on-hazard, route-inactive and return steps;
- the shared mission-goal ranking.

BD and BF:
- Same as LO.
- Before R-1, the P count reached them on every hand-back step. After R-1 it no longer reaches them systematically once N_unf = 0, but it still does on LO-rule fallbacks (C4).
- H0 equals the uniform spawn distribution by construction (stated as a design fact, not a run-time read).
- The only managed read is the boolean confirmed flag, which is detection-derived.

RW:
- No P on its own steps: a draw exists every step, so the current chain never steers it.
- Only the inert P handled-check runs before the hook.

ALL:
- Firefighter dispatch and tracking use the true victim cell (A7).
- The mission-goal count.

M2 - THE fix3b STRATEGIES AND THE SHARED PIPELINE
================================================================================================================
No fix3b strategy reads managed truth (class P). This holds for LO, BD, BF (including the R-1 least-observed continuation) and RW.

- **Detection events.** The belief's only read of managed state is the boolean `managed_victims[vid].confirmed` together with the keys of `victim_runtime_model.victims` (wildfire_model.py:2767-2771). Both are written only by the sensor path:
  - `confirmed` is set at the first in-radius detection (wildfire_model.py:1459-1462), or at dispatch, which itself requires `confirmed` (4926; rescue_planner.py:593; 3622-3627).
  - The `rescue_executor` "confirm" branch (rescue_executor.py:94-103, 566-568) is unreachable in practice, because no MAPE rescue option carries a victim_id (rescue_adaptation_generator.py:22-34, 157-305). This is inferred.
  - Runtime-model records are created only inside the detection pass: `update_detection` at 1446 and `require_confirmation` at 1455-1458. The re-read at 1510 uses `visible_victim_candidates`, which comes from existing records only (local_uav_monitor.py:95-112), so it is a closed loop.
- **The count.** N is the briefing count `NUM_VICTIMS` (B). N_unf = N minus distinct first detections (S). No count that includes undetected or dead victims is read.
- **Other inputs.** None of these strategies reads wind (verified: no wind token in searcher_targeting.py or victim_search_belief.py, nor in the belief update or the BFS). The true fire and smoke come from the schedule's Fire agents (A3). Positions are the UAVs' own (S). The motion parameters are literature assumptions (D), not the simulator's flee rule (P). RW reads only its salted RNG stream, the grid bounds and other UAVs' cells; it is fire-blind at the primary RW_GATED 0.

**Where P still reaches the system: the shared pipeline only.**
1. On steps without a delivery, the current chain steers (no feasible target, the R=10 hold, fail-safe pre-dispatch calls). That chain reads `_count_unresolved_victims` (local_adaptation_generator.py:763-789, 1350), which includes undetected victims and drops unseen-dead ones. After R-1 this exposure no longer occurs once all victims are detected. It never reaches RW.
2. Firefighter dispatch and tracking read the true victim position after detection (A7), identically in every arm (wildfire_model.py:3603-3627, 4882-4890; agents.py:2785-2803).
3. The uniform spawn rule is never read, but its support is built by the same `victim_search_prior_excluded()` call as the prior. H0 therefore equals the generating distribution by construction; the paper should state this.
