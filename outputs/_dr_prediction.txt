  ARM A (hard filter) is bit-identical to arm none on all 23 runs.
    The filter removes candidates with reach == False.  No candidate in the
    sample has reach == False, so the kept pool always equals the full pool
    and the Manhattan sort runs on an unchanged set.  The empty-pool branch

  ARM B (soft tiebreak) is bit-identical to arm none on all 23 runs.
    The sort key (manhattan, not reach, id) collapses to (manhattan, id) when
    every reach is True, which is exactly the stock key.  0 dispatches flip.

  ARM BT (thresholded soft tiebreak) is bit-identical for the same reason,
    at any threshold.

  D/east 505 does NOT recover its rescue under either arm.  At step 97 both
  ff_unit_0 (Manhattan 46) and ff_unit_1 (Manhattan 47) have an OPEN route to
  victim_1.  A reachability-aware tiebreak has nothing to prefer, so the
  1-cell Manhattan margin still decides and still picks ff_unit_0.

WHAT WOULD FALSIFY THIS: any cell where arm A or arm B produces a different
per-step trace, any nonzero arm_changed count, or any empty-pool firing.
The arms are being run anyway - a prediction derived from the same probe that
would confirm it is not evidence, and the point of running them is that the
arm code paths could have a side effect the analysis does not model.
