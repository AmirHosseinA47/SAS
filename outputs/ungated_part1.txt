0. SUMMARY
--------------------------------------------------------------------------------
THE FLIP IS SMALL:
  - 4 constants
  - 4 accessors: 10 literal sites plus 3 truncation holes, rewritten on one exact-integer
    helper
  - 16 comment or text sites
  - 3 deliberate test pins
  - 8 one-token runner pins
MEASURED (section 2.4): flipping the four constants in a full-suite run fails exactly
the two deliberate pins and nothing else. 8 -> 10 failed, and the 8 known failures fail
for the same reason. The flip is test-cheap for a worrying reason: no behavioural test
outside the mechanic's own file notices firefighters fighting fire from step 1.

EIGHT OF THE BRIEF'S PREMISES NEED CORRECTING (section 1). Three change the design:
  P1 THE BASE STATION IS NOT A CHANGE SINCE THE COST WAS MEASURED.
     - Both fire-mechanic rounds descend from the flip commit 68c75a9 and ran at dcD.
     - Firefighters already spawned in the depot then.
     - Two things did change after the measurement:
         - non-burnable depots (6668368)
         - the searcher guard (629a321)
       Both change the world, so the cost must still be re-measured.
  P3 "-6/72 UNDER CRN" IS THE DRY ARM (positioning alone, no writes).
     - The configuration this round ships was measured in the same instrument at -3/72.
     - So which CRN threshold gates the shipped arm is a maintainer decision (Q2).
  P8 THE ROUND-1 ANALYZER WOULD PUT THE FEATURE ARM 50 CELLS PER RUN BELOW THE CONTROL.
     - Cause: depot cells are counted as "cleared".
     - The bias is the same order as the effect being measured.
     - Intact vegetation is redefined in 6.4.

ACCESSOR PATTERN (section 4):
  - Only an EXACT integral zero disables.
  - A MISSING attribute takes the SHIPPED value.
  - Anything that is not an exact integer ARMS.
  - Implemented on one helper that never raises and closes all three holes the common
    pattern still has: non-integral truncation, Decimal/Fraction truncation, inf.
  - Measured on 27 edge values before and after: outputs/_ug_accessor_matrix.txt.

PRE-REGISTERED FOR PART 3 (section 6):
  - A fresh set of 30 seeds, chosen by code before any run, used by no prior round
    (outputs/_ug_seeds.txt).
  - 10 arms, 280 harness runs + 8 route_blocked shards.
  - Gate formulas fixed now, before any number exists.

THE RULE, for every switch this round changes:
  (i)   Only an EXACT integral zero disables.
  (ii)  A MISSING attribute takes the SHIPPED value. So "missing" can never silently
        disagree with the default.
  (iii) Anything that is not an exact integer - junk, None, non-integral float, inf,
        nan, non-integral Decimal/Fraction - ARMS. Nothing can silently take the zero
        path.
  (iv)  The accessor never raises.

WHY NOT THE COMMON PATTERN (base_station_fireproof, agents.py:1064-1086). Measured in
_ug_accessor_matrix.txt, it still has three holes:
    - `int(Decimal('0.5'))` and `int(Fraction(1,2))` truncate to 0 and pass the float
      test
    - `int(float('inf'))` raises OverflowError
    - the searcher guard's `level <= 0` disarms on -1
  The helper below has none of them. It is used by the four CHANGED switches only.
  Retrofitting the other 16 accessors (and DRY_RUN) stays with the accessor round, per
  the maintainer's ruling.

  def _exact_integer(raw):
      """raw as an int iff it denotes an exact integer; else None. Never raises."""
      if isinstance(raw, bool):   return int(raw)
      if isinstance(raw, int):    return raw
      if isinstance(raw, float):  return int(raw) if raw.is_integer() else None
      if isinstance(raw, str):
          try:    return int(raw.strip())          # "0.5", "off", "" -> None
          except ValueError: return None
      try:    value = int(raw)                     # Decimal, Fraction, numpy ...
      except (TypeError, ValueError, OverflowError): return None
      try:    return value if raw == value else None
      except Exception: return None

  EXTINGUISH, FIREBREAK   v = _exact_integer(getattr(cfv, NAME, 1))
                          -> True if v is None else v != 0
  ENGAGED_RETREAT_RANGE   v = _exact_integer(getattr(cfv, NAME, 1))
                          None or negative -> 1 (shipped)
                          0                -> 3 (the kill switch: no suppression)
                          1, 2             -> v
                          >= 3             -> 3 (an explicit unsuppressed buffer)
      A DISTANCE, not a switch. 3 is an explicit value still in use: round 1's fmF/fmEF
      arms and the test helper's retreat_range=3. It is not junk. A negative is junk,
      and ARMS.
  MISSION_GATE            v = _exact_integer(getattr(cfv, NAME, 0))
                          -> True if v is None else v != 0
      The one switch whose shipped value IS the zero:
        - missing -> 0, agreeing with the shipped default
        - junk    -> gate ON. A typo can only CLOSE the gate, and that can only make the
          feature more rescue-neutral. Round 2's guarantee is kept.
