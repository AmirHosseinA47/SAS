1. THE CRITERION - WHEN A SETTING IS "RING-SPECIFIC"
  Every constant in the current chain was set or kept while the fixed ring was the only spawn (15.1 c), so
  "measured on the ring" cannot be the test - it would cover every number in the chain and no neutral
  replacement exists for most of them. The test used here is what the setting ENCODES:
    RING-SPECIFIC (replaced) - the setting
      (i)   names an absolute grid cell or coordinate, or
      (ii)  makes the searcher prefer one compass side, or behave differently under one named wind, in a
            way not derived from the fire (downwind / upwind) or from the searcher's own state, or
      (iii) is justified in its commit or code by ring victim positions or ring-only diagnoses, or
      (iv)  is asymmetric across compass directions with no stated derivation (it cannot be shown general,
            so it is treated as tuned).
    GENERAL (kept) - the setting is expressed relative to the grid bounds, the fire, the sensor or the
    searcher's own history, is symmetric under reflecting the grid together with the wind, and either fixes
    a defect that occurs whatever the victim placement (livelock, unreachable release, camping,
    oscillation, hazard) or is a plain design weight.
  RESIDUAL (stated, not removed): general-form weights selected under ring-only gates (15.1 c). See 2.4.
  The rule for a defect fix: KEEP THE FIX, REMOVE THE SIDE. Where a general defect (edge camping, an
  unreachable release) was fixed on one side only, the untuned search applies the same fix on both sides.

  THE RING, for reference (wildfire_model.py:950-968, N = 5, 50 x 50): victims at about (40,25), (32,46),
  (13,34), (7,12), (30,11) - x = 40, 32, 13, 7, 30. The absolute constants below sit on this geometry:
  38 just west of the x = 40 victim; 12 just east of the x = 7 / 13 pair; 25 and 8 / 30 bracket it.

3. ITEM 2 - PRIVILEGED READS AND WHAT REPLACES THEM
3.1 THE REPLACEMENT COUNT (one function, used everywhere below)
  KNOWN_UNRESOLVED = N_brief - #rescued - #observed_dead
    N_brief        = the model's NUM_VICTIMS (the scenario's briefing count, class B; the fix3b belief's
                     n_brief reads the same global, wildfire_model.py:2715). Never len(managed_victims).
    rescued        = managed state.rescued or state.status == "rescued" - set only by finalize_rescue
                     (wildfire_model.py:5103-5125), a completed rescue the team carried out (S).
    observed_dead  = dead AND confirmed. confirmed is the detection flag: set at first in-radius detection
                     (:1459-1462) or at dispatch, which requires it (:4926); never reset (grep: only True
                     writers). A death is OBSERVED iff the victim had been detected (decision D-2): the
                     team holds its position (runtime record) and, from dispatch, tracks it (A7). A victim
                     that dies undetected is never observed: the detection pass skips dead markers
                     (:1427-1436), so it stays counted - a real team keeps looking for it.
  The marker objects (victim_marker_agents) are NOT read. "Unreachable" / "cancelled" are NOT subtracted
  (decision D-3: the instruction's formula; an unreachable victim is detected, alive and unresolved).
  Properties: KNOWN_UNRESOLVED >= the privileged count at every step (it subtracts a subset). They differ
  exactly when a victim died unseen or was declared unreachable; their ">0" tests differ only when the
  privileged count is 0 and the known one is not - i.e. in the END GAME, when every remaining victim died
  unseen or is unreachable. There the shipped chain drops out of coverage mode ("knows" nothing is left)
  and the untuned chain keeps searching.

4. THE BAYESIAN ARMS' HAND-BACK (confirmation requested)
  On a hand-back step (R-1 residual: LO no-tile hold, on-hazard skip, route-field-inactive, return legs,
  fail-safe pre-dispatch; map C4 / 17.3) the current chain steers. With SEARCHER_UNTUNED = 1 that chain
  reads KNOWN_UNRESOLVED (B + S) instead of P1, the post-rescue gate reads it instead of P2, the mission
  goals carry it instead of P3, and the marker read P4 is skipped. The strategies' own reads are P-free
  (map M2: the belief reads only the confirmed flag and runtime-record keys). So with the switch on, NO
  privileged victim information reaches a Bayes arm on any step; A3 (true fire) and A7 (firefighters) are
  unchanged assumptions. Part 2 verifies it by test (6.2 c) with SEARCHER_TARGETING 2 and 3.
  CAVEAT, NOT A CHANGE: this holds only for Bayes arms RUN WITH THE SWITCH ON. Whether the measurement
  round does that is the maintainer's decision; this round does not amend the measurement round.
  The hand-back steps also run under the untuned settings of item 1 (same switch).

     The two privileged counts answer different questions, so they get different replacements:
       SEARCHER COUNT (P1 and the post-rescue gate P2) - "is any victim still to be FOUND?"
         KNOWN_UNDETECTED = N_brief - #detected
         detected = confirmed (the detection flag, 3.1) union the runtime-record ids, as the fix3b belief
         builds detected_ids (wildfire_model.py:2767-2771). A detected victim - alive, awaiting rescue,
         unreachable or dead - no longer needs searching. A victim that died unseen stays counted, as for
         a real team.
       MISSION-GOAL COUNT (P3) - "is the mission finished?"
         KNOWN_MISSION_UNRESOLVED = N_brief - #rescued - #observed_dead   (3.1 as written)
         Unreachable victims stay counted.
     WHY THEY DIFFER: the single formula of 3.1 used for the searcher would have counted detected victims
     awaiting rescue (or declared unreachable) as unresolved, keeping searchers in coverage mode hunting for
     victims already found. Finding and finishing are different questions.
     CONSEQUENCES FOR THE DESIGN (supersede 3.1's "Properties" for the searcher count):
       - Every consumer of the searcher count tests only "> 0" (coverage mode :812, priority :1384, hybrid
         :1409-1428, y-commit :1274, planner :132-141, the post-rescue gate). Against the privileged count
         the ">0" test differs in TWO cases:
           (A) ALL FOUND, NOT ALL FINISHED - every victim detected, some still awaiting rescue or
               unreachable: privileged > 0, known = 0. The untuned searcher LEAVES coverage mode at the
               last detection; the shipped one stays in it until the last victim is resolved. COMMON: it
               occurs in every run in which all victims are detected before all are resolved.
           (B) ONLY UNSEEN DEAD LEFT - every undetected victim has died unseen and the rest are resolved:
               privileged = 0, known > 0. The untuned searcher keeps searching; the shipped one stops.
         Before the last detection both counts are > 0 (an undetected victim is either alive - counted by
         both - or dead unseen - counted by the known count), so item 2 cannot change a step before the
         last detection or before case (B). It therefore cannot change any detection time by itself: after
         the last detection there is nothing left to detect, and in case (B) only dead victims remain.
       - The mission-goal count is >= the privileged mission count (it subtracts a subset) and differs in
         its ">0" test only when every remaining victim died unseen or is unreachable.
