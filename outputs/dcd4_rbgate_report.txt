ihrest's, and Z regresses on NO seed. Not one of the four regressions reproduces
without dcD's settings, so by the declared rule each is caused by them: NEW.
Because ihrest is itself a mode-0 run, CARRIED could only have arisen from HEAD's
mode 0 drifting from ihrest, which committed data (rbc == ihrest) already made
unlikely; the label was the expected one, and the wave's new content is the
identities D == K == dcrbD and Z == rbc.

    seeds with the same values. Every drgD shard is identical to its dcrbD shard on
    every field except tag and wall_s: evals, every hook counter, every per-step
    fire and recovery record.

    dock-fix round showed at dcB's. Nothing between 9f77178 and 8414add moves it.

"PRE-EXISTING" MEANT TWO DIFFERENT THINGS. The brief says the depot round's [FAIL]
was established as pre-existing because the fix-absent arm produces identical
numbers. That is what the dock-fix round established: pre-existing RELATIVE TO THE
DOCK FIX. Its own text (dockfix_report.txt 4.8) says the same comparison "measures
ARMING THE BASE STATION - the depot-cost round's already-reported cost". This round
finds the same shape at dcD's settings:
  - pre-existing relative to the dock fix;
  - caused by dcD's settings relative to the shipped default.
The brief's step-2 test asks the second question. By it the failure is NEW.

the dock fix absent" (K, dcrbD - the test the dock-fix round ran), all four
regressions would be CARRIED and the precondition MET. That test does not run the
seeds WITHOUT dcD's settings, so it is not the rule step 2 defines or the one

weigh it.
