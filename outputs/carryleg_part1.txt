0. SUMMARY
================================================================================
  Three independent switches, one per defect. Each is off only at an EXACT
  zero, and each is measured in its own arm.
    FF_EXIT_LEG_MODE (D1)
      0  today's behaviour.
      1  complete the rescue on ANY boundary cell.
      2  mode 1, plus: on each carrying step, take the first step of a
         breadth-first search over clean cells to the nearest boundary cell.
         This is exactly the rule the diagnosis defined and replayed. With no
         clean path, fall back to today's rule, unchanged.
    FF_EXIT_LEG_HOLD (D2)
      0  today's behaviour.
      1  an enclosed carrier holds its cell and keeps its victim. It never
         raises route_blocked, so it is never unassigned and never drops the
         victim. While it holds, its cell counts as a reachability start, the
         same start today's dropped ex-carrier provides.
    FF_EXIT_LEG_SERVED (D3)
      0  today's behaviour.
      1  a victim in a live carrier's custody counts as served, so its
         isolation streak cannot run.
      2  (proposed, recommended NOT for this round, D-1) rung 1, plus a live
         carrier's cell counts as a reachability start for other victims.
  All three ship at 0 through Parts 2 and 3, so the default tree is
  value-identical to 6160438 by construction. A fix that passes is flipped ON
  in a separate final commit, with its own identity gate (section 7).

2.3 MODE 2 - MODE 1 + THE FIRST STEP OF A CLEAN-CELL SEARCH
  This is the diagnosis's own mode-2 definition (outputs/exitstall_part1.txt:
  628-633): "The search runs over clean cells: not burning, not fire-adjacent,
  not smoky ... With no clean route it falls back to today's rule". The brief's
  "fire-free search path" summarises it. It is also exactly the rule the
  offline replay estimated (_cl_replay/fs_rules.py:82-101, bfs_first_step,
  strict=True).
  2.3.1 HOW THE PATH IS COMPUTED
    On every carrying advance at mode 2, after the mode-1 completion test has
    failed (so the carrier is NOT on a boundary cell):
      - Breadth-first search from the carrier's cell over 4-neighbours.
        - Order: a NEW constant, EXIT_LEG_SEARCH_ORDER = (+x, -x, +y, -y),
          pinned by a test. It deliberately does NOT reuse
          ORTHOGONAL_OFFSETS, which is documented as the victim-flee
          tie-break; a future flee change must not move mode 2.
      - The START cell is exempt from every test. That matters for a smoky or
        fire-adjacent start. A burning start always falls back: every
        neighbour of a burning cell is fire-adjacent, so the fallback is
        bit-for-bit today's tier-4 step.
      - A cell may be entered iff it is in bounds and CLEAN:
            not burning        (_cell_contains_active_fire)
            not fire-adjacent  (no in-bounds 4-neighbour burning)
            not smoky          (_cell_has_active_smoke)
        This is _move_toward's own tier-1/3 clean test, using the unit's own
        helpers. A per-call memo of the burning test keeps it to one grid read
        per cell.
      - GOAL: any cell with an out-of-bounds 4-neighbour. The goal test runs
        at discovery, AFTER the clean test, so a fire-adjacent or smoky
        boundary cell is never a goal. The first goal discovered is at minimum
        depth; ties go by discovery order.
      - RESULT: the path's first cell, recovered through first-discovery
        parents. Then:
        - the carrier moves there;
        - the victim follows (the existing lines 1841-1847);
        - _last_move_tier = 5 (label only; nothing reads the tier as a
          number), and _last_move_risk = 0;
        - _move_toward's status tail is applied: a unit labelled route_blocked
          that moves is relabelled "assigned", as at 2460-2463.
    THE KERNEL is a module-level pure function,
        exit_leg_first_step(start, passable, is_boundary, out_of_bounds, order)
    so the replay can drive the implemented search itself (section 8.4).
  2.3.2 HOW OFTEN
    - Once per carrying advance, at most one search per unit per step.

    - No RNG draw.

    cell is non-burning, so no fire-free path implies no clean path, and the

        from the same cell.

      victim's streak resets exactly as after today's drop, and no other
      victim's flags change.

5.1 ACCESSORS (agents.py, beside ff_firefight_*, built on _exact_integer)
  The rule:
      exact 0 (0, 0.0, "0", False)  -> off. This is the kill switch.
      missing attribute             -> the SHIPPED value, i.e. the cfv
                                       default (0 until a fix is flipped).
      junk, None, non-integral, "", -> ARMS: never the zero path.
      inf, nan, Decimal("0.5"), ...
      never raises
  THE BRIEF-MANDATED EXCEPTION, written into the shared comment block:
  common_fixed_variables' rule sends junk to the SHIPPED value. For a switch
  that ships at 0 that would be the zero path, which "disables only on an exact
  zero" forbids. So while a switch ships at 0, junk maps to a named non-zero
  value. At the flip, junk maps back to the shipped value (D-2).
    ff_exit_leg_mode() -> int     exact 0 / 1 / 2 -> that mode;
                                  anything else (junk, None, 0.5, negative, an
                                  integer >= 3) -> 1
    ff_exit_leg_hold() -> bool    exact 0 -> False; any other exact integer,
                                  negative included (as in
                                  base_station_fireproof) -> True; junk -> True
    ff_exit_leg_served() -> int   exact 0 / 1 -> that rung; anything else -> 1
                                  (2 only if D-1 approves rung 2; until then the
                                  queue generator and the analyzer REFUSE any
                                  run that sets SERVED=2, so it cannot be
                                  silently absorbed as 1)
  common_fixed_variables.py gets
      FF_EXIT_LEG_MODE = 0, FF_EXIT_LEG_HOLD = 0, FF_EXIT_LEG_SERVED = 0,
  with a comment block in the file's own style.
  - They are read at CALL time through `cfv`: never through agents.py's star
    import, never at import time. So an apply_scenario_config / --set override
    is visible; otherwise the switch would be decorative (the dead-input

9.3 WHAT IS MEASURED
    Per arm, per set, per instrument. Every run: --steps 360 --set
    BATCH_SIZE=360 --uav-actions, through the sidecar. CRN arms compare only
    with CRN arms.
  ROW CONVENTION: an event stamped s happens during model step s. ff_steps[s-1]
  and ff_bind_steps[s-1] are the state AFTER step s; the state at the START of
  step s is row s-2.
  M1 EXIT LEGS. A leg is a (unit, victim) exit_start, paired with the
     completion by that unit. (The census paired on victim only.)
     M1a  STALLED iff n > d_c + 5, with d_c = manhattan(pickup, completion
          cell completions[].pos). This is the diagnosis's gate definition
          ("measure the stall to the COMPLETION cell").
     M1b  STALLED iff n > d + 5, with d = manhattan(pickup, fixed exit_target)
          = distance to the nearest boundary. Census-comparable.
     M1c  STALLED-OR-BROKEN, per exit_start. Counted if any of:
            - completed with M1a stalled;
            - ended without completion (drop, died, isolation release);
            - cut at the horizon with elapsed > d + 5.
          THE G2 COUNT: a conversion moves a leg from broken to completed and
          leaves M1c unchanged.
     Also: excess steps and reversals. Conversions (broken in clC, completed
     in the arm) are listed on their own line with their length and d.
     MATCHED COVERAGE: legs matched on (tuple, instrument, unit, victim,
     pickup step and cell), over all clC legs and all arm legs, split at each
     tuple's first divergence step (ff_steps and fire_digests):
       - a PRE-divergence leg that does not match is an analyzer defect: STOP;
       - POST-divergence legs are reported side by side with clC's (count,
         broken, total and max excess, stalled), and arm legs with no clC
         counterpart are listed.
     Expected coverage: the legs picked up after the first changeable leg are
     1-8% of all legs (uhD 3/103, ugKD 2/96, f2cEFS 6/74).
  M2 BROKEN CARRIES, by the unassign reason at the end step:
       drop                replacement_after_blocked
       died in custody     firefighter_fire_casualty of an exiting unit (the
                           ff_steps death row has exiting False; key it on the
                           previous row)
       isolation release   geographically_isolated
       horizon
  M3 DROPS CONVERTED. Every clC drop, matched to the same carry in the arm,
     ends as one of:
       completed (CONVERTED) / died in custody / isolation release / horizon /
       unmatched
     Each HOLD trigger is classified A/B/C/D (the drop classes, section 1).
  M-HOLD, exact from ff_steps + unassigns + burn_intervals, cross-checked
     against the sidecar.
     A held advance at t: row t-1 exiting and alive at p; row t exiting and
     alive at p; no completion at t; every in-grid neighbour burning. A carrier
