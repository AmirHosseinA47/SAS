0. THE SHORT VERSION
--------------------
  * WildFireModel never stores its size. Verified three ways on this tree: no
    `self.HEIGHT/WIDTH/height/width/grid_height/grid_width` assignment anywhere in
    wildfire_model.py (grep); none of the six names exists on mesa.Model, on the
    WildFireModel class, or on a freshly built instance (hasattr, run under the .venv);
    `git log -S'self.HEIGHT' -- wildfire_model.py` is empty over all 50 commits. The
    attribute has never existed.
  * 13 source sites (plus 2 in tests) ask the MODEL for its size through a defaulting
    read. 10 of the 13 default to the literal 50, which is numerically right at 50x50, so
    the fix changes NOTHING at those sites on this grid. The other 3 go through
    UAVExecutor._grid_dimension, which returns None instead of a default, and the code
    behind those three has never run in a real simulation:
      - _position_at_boundary  (uav_executor.py:540)  always False today
      - _distance_from_boundary (uav_executor.py:552) always 0.0 today
      - the search-offset clamp in _execute_search_mode (:803-807)  NEW - a third wake
        site the diagnosis did not list; it skips the clamp when the size is unknown.
  * Between them the two helpers feed NINE consumers (the diagnosis listed five). All are
    movement decisions: hold-escape, hazard-escape scoring, the victim-searcher edge
    retarget, the interior retreat, and the searcher hazard gate.
  * Re-verified effect, recorded shim50 arm against the recorded baseline, seed for seed
    (section 4): 0/13 runs identical; rescued 35 -> 37, dead 12 -> 11, ff_deaths 8 -> 8
    but moving on four seeds (two down, two up), never_detected 1 -> 2. The +2 is
    E/half 505 (+2), S/half 303 (+1) and E/half 303 (-1, with one victim written off).
    Concentrated, single-sample, not yet a clean win.
  * Proposed fix: two lines in WildFireModel.reset(), immediately after the grid is built:
    `self.HEIGHT = HEIGHT` / `self.WIDTH = WIDTH`. Nothing else. No site needs more than
    the raw dimension (section 5.2). Control for the byte-identity proof: a harness-side
    hook that makes the two attributes raise AttributeError on read, so every defaulting
    read resolves exactly as it does at 8520706 - no debugging flag added to the source
    (section 5.3; a source-level switch is offered as the alternative).
  * Validation (section 6): fresh baseline at 8520706, fix arm, control arm (must be
    byte-identical to baseline), instrumented arm (must be byte-identical to fix; gives
    the per-helper firing tables with a decision-level counterfactual), three one-site-live
    ablation arms so the +2 can be attributed to a helper rather than to "the fix", the 10

3.2  What they are supposed to do
  _position_at_boundary: "is this UAV standing on an edge cell" (x or y at 0 or max-1).
  _distance_from_boundary: the cell's distance to the nearest edge, 0 on the edge.
  Together they implement the executor's edge awareness: keep UAVs off the border, push
  a UAV that is holding or escaping on the border back into the interior, and prefer
  interior cells when several escape/retreat directions are otherwise equal.

3.3  Why they never execute (the defaults are reached by a path that cannot resolve)
  _grid_dimension probes three names per axis on the model. The model has none of the
  six (section 0), so getattr(model, name, None) is None three times and the function
  returns None; both helpers then take their `is None` early return. For the literal-50
  sites the shape is getattr(model, "HEIGHT", getattr(model, "height", 50)): Python
  evaluates the inner default first, which is also missing, so the 50 is produced before
  the outer lookup even runs. Nothing on the real model has ever satisfied either probe:
  the helpers, _grid_dimension and the agents.py read all arrived in the initial import
  a4a01b4 (2026-07-27) and wildfire_model.py has never carried the attribute since.

5. THE FIX
----------
5.1  Shape
  wildfire_model.py, WildFireModel.reset(), immediately after :132
  `self.grid = mesa.space.MultiGrid(HEIGHT, WIDTH, False)`:

        # Expose the grid extent on the instance. Every dimension read in
        # agents.py and src_extension/ asks the MODEL for HEIGHT/WIDTH and
        # silently falls back to a literal 50 (or to None, which disables the
        # executor's boundary helpers) when the attribute is missing - and it
        # always was. Same globals the grid was just built from, assigned in
        # the same call, so the two cannot disagree. mesa's MultiGrid takes
        # (width, height): grid.width is HEIGHT (the x extent), grid.height is
        # WIDTH (the y extent), which is why these are not derived from it.
        self.HEIGHT = HEIGHT
        self.WIDTH = WIDTH

  Two assignments plus a comment. reset() (not __init__) because reset() rebuilds the
  grid and is the entry point the dashboard's reset button uses; __init__ calls reset().
  Placed before set_fire_agents(), UAV placement and _init_managed_* so nothing can read
  the model before the attribute exists. Uppercase names only: they are the names every
  site probes first (after "grid_height"/"grid_width", which nothing sets) and they match
  the existing `self.NUM_AGENTS = NUM_AGENTS` convention in __init__. Lowercase
  height/width are NOT added: nothing needs them once HEIGHT/WIDTH exist, and they are the
  mesa grid's own attribute names with the opposite axis meaning. CRLF preserved
  (wildfire_model.py: 5312 CRLF, 0 bare LF).

5.2  Sufficiency - does any site need more than a value?
  No. Every consumer derives its own bound (H-1, W-1, H+W+5) from the raw extent; none
  expects a pre-computed bound, a tuple, or a callable. _grid_dimension applies int()
  itself. apply_scenario_config(cfv, wf, HEIGHT=..) sets the wf module global that both
  the grid and the new lines read, so a runtime override stays consistent (global_monitor's
  import-time binding, W3, is a separate defect and stays out of scope). The only sites
  that would still be wrong on a NON-square grid are the two swapped fallbacks noted in
  1.3 and 3.1, which are W5 and unreachable/harmless here.

  Explicitly NOT done this round: no change to _grid_dimension or to any literal default
  (they become unreachable-by-construction on the real model, and the fakes in tests
  still rely on the getattr shape); no change to the swapped fallbacks; no test edits; no
  dashboard change; nothing in global_monitor.

5.3  Kill switch / control
  Recommended: NO source-level switch. Features 1 and 2 carried --set switches because
  their parameters are legitimately tunable; a flag whose only use is to re-enable a
  defect would be a permanent debugging knob in common_fixed_variables. The brief allows
  "or equivalent control", and an exact one exists without touching the source:

    In the harness, replace WildFireModel.HEIGHT / .WIDTH on the CLASS with a property
    whose setter stores the value in instance.__dict__ (so reset()'s assignment succeeds)
    and whose getter RAISES AttributeError. getattr(model, "HEIGHT", 50) then returns 50
    and _grid_dimension's getattr(model, name, None) returns None - the reads are forced
    back to the hardcoded default by the same mechanism that produced it at 8520706.

  This is the battery round's validated class-property hook with a denying getter. The
  control arm must be byte-identical to the 8520706 baseline on every recorded field
  (fire digests, ff_steps, victim_steps, eval, planner, assigns, stdout sha256). If the
  maintainer prefers a source-level switch for symmetry with Features 1 and 2, the
  alternative is one constant (e.g. EXPOSE_GRID_DIMENSIONS = True in
  common_fixed_variables) guarding the two lines; say so at confirmation and Part 2 adds
  it. I would rather not ship a flag that exists only to break the model.

6.1  Arms on the canonical 13 (D/east half 101-505, D/south half 101-505, D/east default 101/202/303)
  dimbase   8520706 in a detached worktree (`git worktree add --detach`), stock harness.

            box today).
  dimfix    patched working tree, stock harness. Cross-check: eval per seed vs shim50.
  dimctrl   patched tree + denying property hook. GATE: byte-identical to dimbase.
  diminst   patched tree + recording property hook + helper observers. GATE: byte-
            identical to dimfix (the observers are pure: call the original, return it
            unchanged, draw nothing from any RNG, mutate nothing). Records:
              - every read of HEIGHT/WIDTH by caller (file:function:line) and step;
              - every call of P and D with (step, uav, role, pos, result);
              - for each of the nine consumers, the real result AND a counterfactual
                result computed by calling the same consumer again with the reads
                denied (a per-call toggle on the hook), so "decision changed by the live
                value" is measured at the decision, not inferred from trajectories.
                The consumers are pure reads except two idempotent memo/state
                initialisations (_get_tracker_hazard_cache, _wind_search_state, the
                hazard_buffer_level/force_coverage_escape writes in the hazard gate);
                double evaluation leaves identical state - and the byte-identity gate

              - per-step UAV positions and executed (direction, action) per UAV, so the
                first divergent UAV step per run can be matched to the first changed

7. RISKS STATED BEFORE RUNNING
------------------------------
  - Trajectory-based tests on the real model may flip either way; two of the eight
    baseline failures are trajectory tests. A newly-passing test is reported but is not
    a gate item; a newly-failing one fails the gate.
  - The instrumented arm's double evaluation touches two memo/state initialisers; the
    byte-identity check against dimfix is the proof it is inert. If it is not identical
    the instrumented numbers are discarded and the observers reduced to pure reads.
  - The +2 is E/505 +2, S/303 +1, E/303 -1. One seed carries the headline. The fresh
    seeds and the ablations are the only things that can turn that into a claim.
  - This re-baselines 50x50 for every future round (0/13 identical). If shipped, the
    canonical gates recorded before it (latbase/phfix3 numbers) stop being the
    comparison point and the report will say which files become the new baseline.
